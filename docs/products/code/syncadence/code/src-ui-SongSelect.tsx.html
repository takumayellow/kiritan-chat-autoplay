左に曲の一覧、右に選んだ曲の詳細（難易度ごとのレベル・ノーツ数・ランク、自己ベスト、PLAY ボタン）を並べ、矢印キーと Enter でも操作できる選曲画面の部品です。

このファイルが担うもの

  • 曲の一覧を、ジャケットの代わりの色付きの四角・曲名・作曲者と長さ・ランク・レベルの 1 行ずつで並べる（L92-119）。

  • 選んだ曲が一覧の見える範囲に入るよう、一覧をスクロールする（L65-67）。

この部品はどの曲・どの難易度を選んでいるかを自分では覚えていません。選んだ曲は selectedId、難易度は difficulty として App から受け取り、変えたいときは onSelect・onDifficulty で App に頼みます。自分で覚えているのは、引き出しが開いているかどうか（drawerOpen）だけです。

型の項目名の後ろに ? を付けると（large?: boolean）、その項目は書いても書かなくてもよいことになります。書かなかったときに読むと undefined です。

この useEffect は、選曲画面にいる間、キーボードの操作を受け付けます。

window.addEventListener("keydown", onKey) は、「ページのどこでキーが押されても onKey を呼んで」とブラウザに頼む書き方で、L62 で返している関数がその頼みを取り消します（文法の索引の『イベントリスナーの登録と解除』）。useEffect の後片付け（文法の索引の『useEffect』）として取り消すので、選曲画面から別の画面に移ると、キーの受け付けも止まります。

L45-60 の onKey は、キーが押されるたびにブラウザから呼ばれる関数です。受け取る e には押されたキーの情報が入っています。

  1. L46 — Ctrl・⌘・Alt と一緒に押されたか、入力欄にいるなら何もしない。Ctrl+R（ページの再読み込み）や Alt+←（戻る）などのブラウザの操作を邪魔しないため
  2. L47 — いま選んでいる曲が一覧の何番目か（findIndex は見つからなければ −1）
  3. L48-51 — ↑ か ↓ なら、stepIndex で 1 つ上か下の位置を出し（端では止まる、src/ui/select.ts の L17-20）、その曲を選ぶ。songs[位置] は範囲外なら undefined になりうるので、if (next) で確かめてから使う
  4. L52-54 — ← か → なら、stepDifficulty で難易度を 1 つ左か右へ（easy の左と expert の右では止まる）
  5. L55-58 — Enter で、しかもボタンやリンクにフォーカスが無いなら、選んでいる曲を選んでいる難易度で始める

e.code はキーボード上の物理的な位置の名前（"ArrowUp"、"Enter" など）です。e.preventDefault() は「このキーでブラウザが普段することをしないで」という頼みで、↑↓ でページ全体がスクロールするのを止めています。

L55-56 で、ボタンにフォーカスがあるときの Enter を除くのは、ブラウザが「フォーカスのあるボタンを Enter で押す」を自分でするからです。ここでも始めてしまうと、たとえば「タイミング調整」のボタンにフォーカスがあるときの Enter で、調整の画面へ移ると同時にプレイも始まりかねません。

文法: JSX でのイベントの受け取り

<button onClick={関数}> は、「このボタンが押されたら、この関数を呼んで」という書き方です。{ } に渡すのは関数そのもので、onClick={onCalibrate()} のように () を付けると、描くたびにその場で呼ばれてしまいます。

引数を付けて呼びたいときは、L82 の onClick={() => setDrawerOpen(true)} のように、その場でアロー関数を作って渡します。

名前は onClick（押された）、onPointerDown（指やマウスが触れた）、onChange（入力欄の値が変わった）のように on + 出来事の名前です。関数は出来事の情報 e を 1 つ受け取れます。

L72 の className はテンプレート文字列で、たとえば "select theme-hard" になります（文法の索引の『テンプレート文字列』）。CSS の側（src/styles/select.css の L3-14）が theme-easy から theme-expert までに別々の色を割り当てているので、難易度を変えると画面全体の差し色が変わります。

L73-86 は画面の上の帯で、ロゴと 2 つのボタンを並べます。

  • 「タイミング調整」（L79）— onCalibrate を呼び、App が調整の画面へ切り替える
  • 「⚙ 設定」（L82）— 引き出しを開く。aria-haspopup="dialog" は、画面読み上げソフトに「押すと別の枠が開く」と伝える印。歯車の記号は読ませない（aria-hidden）

<main>・<header>・<nav>・<section>・<aside>・<footer> は、見た目は <div> と同じ箱ですが、「ここは本文」「ここは上の帯」のような役割を HTML に書き込むための要素です。aria-label は、目に見える見出しが無い箱に名前を付けます。

文法: JSX の中での条件付きの表示 &&

{条件 && <p>…</p>} は、「条件が真なら <p> を描き、偽なら何も描かない」です。A && B は A が偽なら A を、真なら B を返します（src/storage.ts の『typeof』の囲み）。React は false・null・undefined を何も描かないので、条件が偽なら何も出ません。

条件の値が数の 0 だと、0 がそのまま画面に出てしまう点に注意が要ります。このファイルの条件はどれも真偽か、文字列か、オブジェクトです。

L93-118 は、曲の一覧を 1 曲 1 行で並べます。songs?.map(関数) は、配列の各要素を関数に通した結果の新しい配列を作ります（文法の索引の『map・filter・reduce』）。ここでは各曲を <li>…</li> の JSX に変えた配列になり、{ } の中に JSX の配列を置くと、React はそれを順に並べて描きます。songs が null なら ?. で止まって何も描きません。

L97 の key={song.id} は、並べた要素それぞれの見分け札です（文法の索引の『key（部品の見分け札）』）。並べ替えや追加があっても、React が「どの <li> がどの曲か」を間違えずに済みます。
