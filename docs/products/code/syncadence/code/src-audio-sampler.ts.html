src/audio/sampler.ts

takumayellow/syncadence-v2 の main（404da56）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

本物のピアノを 1 音ずつ録音した音（サンプル）を読み込んでおき、指定された高さ・強さ・時刻・長さでその音を鳴らす、ゲームの「ピアノ」にあたるファイルです。

このファイルが担うもの

  • 読み込み（load、L18-42）: 音源の目録 manifest.json を読み、曲で使う音の高さと強さに必要なサンプルの mp3 だけを、並行して取ってきて音のデータに直す。
  • 鳴らす（play、L45-63）: 音の高さと強さから使うサンプルを選び、再生速度を変えて音の高さを合わせ、強さに応じた音量で指定の時刻に鳴らし、指定の長さの後に音を消していく。

音源は FreePats の Upright Piano KW（CC0、権利の放棄されたもの）です。88 鍵の全部を録音してあるわけではなく、66 個の mp3（弱い音用 30 個、強い音用 36 個）しかありません。録音の無い高さの音は、近い高さのサンプルを少し速く・遅く再生して作ります。

どのサンプルを選ぶか、音量をどうするかの計算は src/audio/regions.ts にあり、このファイルはそれを使って、Web Audio の部品を組み立てて鳴らします。

読みどころ

  • 必要な分だけ読む（L25-29）。曲の音を全部見て、使うサンプルの mp3 の名前を Map に集めます。同じファイルは 1 回しか取ってきません。
  • 音の高さを再生速度で合わせる（L53）。1 半音上げるには、約 1.0595 倍の速さで再生します。
  • 音量の形（L56-62）。指定の時刻に鳴らし始め、長さの分だけ同じ音量を保ち、その後なめらかに消していきます。

落とし穴

  • load を終える前に play を呼ぶと、黙って何も鳴りません（L47・L50）。エラーにならないので、読み込み忘れに気付きにくい作りです。プレイ画面は、読み込みが終わるまで開始できないようにしています（src/ui/Play.tsx の L53-60）。
  • mp3 が 1 つでも取ってこられないと、load 全体が失敗します（L35 と Promise.all）。そのときプレイ画面はエラーの文を出します。
  • 再生速度を変えると音の高さだけでなく長さも縮み・伸びます。高さを 3 半音上げたサンプルは、約 0.84 倍の時間で終わります。音の長さは L62 で止めているので、ふつうは目立ちません。
  • 曲のテンポを落としても音の高さは変わりません。テンポは鳴らす時刻と長さ（engine.ts の L77 で duration / rate）だけに効き、L53 の再生速度は音の高さだけで決まるからです（docs/design.md の 5.1 節）。

L18–L43

文法: Iterable（1 つずつ取り出せるもの）

Iterable<T> は、「for … of で中身を 1 つずつ取り出せるもの」の型です。配列のほか、Map や Set などもこれに当てはまります。引数を配列に限らずこの型にしておくと、呼ぶ側は配列でも別のものでも渡せます。

中身の型 readonly [number, number] は、書き換えない 2 つ組（文法の索引の『タプル型』）です。ここでは [音の高さ, 強さ] を表します。

文法: Promise.all（約束をまとめて待つ）

Promise.all([約束1, 約束2, …]) は、渡した約束が全部果たされたときに果たされる、1 つの約束を作ります（約束は文法の索引の『async / await と Promise』）。await Promise.all(…) と書けば、全部が終わるまで待てます。

1 つずつ await して順番に待つのと違い、全部の処理が同時に進みます。ファイルを 20 個取ってくるなら、1 個ずつ待つより、20 個を同時に頼んでまとめて待つほうがずっと早く終わります。

どれか 1 つでも失敗すると、その時点で全体が失敗になります。

load(notes, onProgress) は、曲で使う音のサンプルを読み込みます。notes は [音の高さ, 強さ] の組の並び、onProgress は読み込みの進み具合を知らせる関数で、省いてもかまいません。

  1. 目録を読む（L19-23）。 まだ読んでいなければ、manifest.json を取ってきて、parseManifest（regions.ts の L21-34）で形を確かめてから覚えておく。取ってこられなければエラーを投げる（fetch の確かめ方は src/song/load.ts の L5-10 と同じ）。
  2. 必要な mp3 を決める（L24-29）。 全部の音について、layerFor で強さから「弱い音用（L）か強い音用（H）か」を決め、findRegion でその高さを受け持つサンプルを探す。見つかって、まだ読み込んでいなければ、ファイル名をキーにして needed に入れる。Map は同じキーに入れ直しても 1 つのままなので、同じファイルが何度出ても 1 回分になります。
  3. 進み具合を 0 で知らせる（L30-31）。 onProgress?.(…) は、関数が渡されていれば呼び、無ければ何もしません（文法の索引の『オプショナルチェーン ?. と ??』）。
  4. 並行して読み込む（L32-41）。 needed.keys() はファイル名を 1 つずつ取り出せるもので、[...needed.keys()]（文法の索引の『スプレッド構文 ...』）でそれを配列にします。その各ファイル名について、map で「取ってきて読み込む」非同期の処理を作り、その約束の配列を Promise.all でまとめて待ちます。各ファイルの処理は次のとおりです。 - L34-35 mp3 を取ってくる。失敗ならエラーを投げる。 - L36 response.arrayBuffer() で中身をそのままのバイト列として受け取り、decodeAudioData で mp3 を音の波の数の列（AudioBuffer）に直す。どちらも時間がかかるので await で待ちます。 - L37 1 つ目の音の通り道（左のチャンネル）の波から立ち上がりの位置を求め、samples に入れる。 - L38-39 読み終えた数を 1 増やし、進み具合を知らせる。

L30 の done は 1 つの変数を全部のファイルの処理が共有しています。終わる順番はばらばらですが、どれかが終わるたびに 1 ずつ増えるので、done / needed.size が「何個中何個読んだか」になります。

例えば「エリーゼのために」の音は全部強さ 62 なので、弱い音用（L）のサンプルだけを読みます。

L44–L64

文法: && で値を選ぶ

A && B は、if の条件の中では「A かつ B」ですが、値としては「A が偽とみなされる値なら A、そうでなければ B」になります。

L49 の region && this.samples.get(region.file) は、region が undefined（見つからなかった）なら undefined、見つかっていれば samples から取り出したサンプル、になります。region が無いのに region.file を読んでエラーになるのを防ぐ書き方です。

文法: べき乗 **

a ** b は「a の b 乗」です。2 ** 3 は 8、2 ** 0.5 は 2 の平方根（約 1.414）です。指数は小数や負の数でもかまいません。

文法: メソッドの連鎖

source.connect(gain) は、つないだ先の gain をそのまま返します。だから続けて .connect(destination) と書けば、「source → gain → destination」と順につなげます。メソッドの戻り値に、さらにメソッドを続けて呼ぶ書き方です。

play(destination, pitch, velocity, when, duration) は音を 1 つ鳴らします。

引数 中身
destination 音をつなぐ先。engine.ts では全体の音量を決める部品（L56-58 の bus）
pitch 音の高さ（MIDI の番号。60 が真ん中のド）
velocity 強さ（1〜127）
when 鳴らし始める AudioContext の時刻（秒）
duration 鍵盤を押している長さ（秒）。テンポを落としたときは engine.ts が伸ばして渡す

Web Audio では、音を作る部品（ノード）を線でつないで、最後にスピーカー（destination）につなぎます。ここでは

サンプルを再生する部品（source）→ 音量を変える部品（gain）→ destination

とつなぎます。

  1. サンプルを選ぶ（L46-50）。 load と同じ選び方で区間を探し、読み込み済みのサンプルを取り出す。目録もサンプルも無ければ何もしない。
  2. 再生の部品を作る（L51-53）。 createBufferSource() で、音のデータを 1 回再生する部品を作る。L53 で再生速度を 2 ** ((pitch − region.key) / 12) にする。region.key はサンプルを録音した高さです。

音の高さは、1 オクターブ（12 半音）上がると振動の速さがちょうど 2 倍になります。だから 1 半音上げるには 2 の 12 乗根 ≒ 1.0595 倍の速さで再生すればよい、というのがこの式です。例えば高さ 63（レ♯）で録音したサンプルで高さ 64（ミ）を鳴らすと 1.0595 倍、62（レ）なら 2 の −1/12 乗 ≒ 0.9439 倍です。弱い音用のサンプルは録音の高さから最大 1 半音、強い音用は最大 3 半音（高さ 42 で録音し 41〜45 を受け持つサンプル。約 1.1892 倍）までずらします。ずらす幅が小さいほど、音色の変化が目立ちません。 3. 音量の部品を作る（L54-59）。 強さから音量 level を決め（regions.ts の velocityGain）、時間に沿った音量の変化を予約する。 - L56 離す時刻 release を when + duration にする。ただし短すぎる音でも 0.05 秒は鳴らす。 - L57-58 when から release までは level のまま保つ。 - L59 release から 0 に向けてなめらかに下げる。setTargetAtTime(目標, 開始時刻, 時定数) は、時定数 0.04 秒（0.12 ÷ 3）ごとに残りが約 37% に縮むように近づける曲線です。 4. つなぐ（L60）。 5. 鳴らす予約と止める予約（L61-62）。 start(when, sample.attack) は「時刻 when に、サンプルの attack 秒の位置から再生を始める」という予約で、先頭の無音を飛ばします。stop で release の 0.24 秒後に止めます。0.24 秒は時定数の 6 倍で、そのころ音量は元の約 0.25%（e の −6 乗）まで下がっているので、止めても音がぶつっと切れたようには聞こえません。

when がすでに過ぎた時刻なら、Web Audio はすぐに鳴らします。キー音（叩いたときに鳴らす音）は、engine.ts の L130 で ctx.currentTime（今）を when にして、この性質を使っています。

音量の部品を音ごとに作るのは、音ごとに強さも離す時刻も違うからです。再生の部品は 1 回しか再生できない使い捨ての部品なので、これも音ごとに作ります。

44 /** when（AudioContext の時刻）に音を鳴らし、duration 秒後に離す。 */
45 play(destination: AudioNode, pitch: number, velocity: number, when: number, duration: number): void {
46 const manifest = this.manifest;
47 if (!manifest) return;
48 const region = findRegion(manifest.regions, pitch, layerFor(velocity, manifest.velocitySplit));
49 const sample = region && this.samples.get(region.file);
50 if (!region || !sample) return;
