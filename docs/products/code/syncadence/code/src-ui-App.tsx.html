文法: 型注釈 : 型

TypeScript では、名前の後ろに : 型 を書いて「ここにはこの種類の値しか入らない」と宣言できます。L25 の songId: string は「songId は文字列」という意味です。

書き方 意味
string 文字列
number 数（整数も小数も同じ型）
boolean true か false
null 「何も無い」ことを表す値
Song、Difficulty など大文字で始まる名前 どこかで定義された型（ここでは src/song/types.ts で定義）

型は TypeScript が書いた時点で検査するためのもので、JavaScript に変換すると消えます。実行中に型を確かめてくれるわけではありません（外から来た値を確かめる話は src/storage.ts で出てきます）。

文法: 型の別名 type と合併型 |

type 名前 = 型; は、型に名前を付ける書き方です。長い型を何度も書かずに済みます。

A | B は「A か B のどちらか」という型で、合併型と呼びます。L26 の number | null は「数か、何も無いか」です。

型の側に "select" のような文字列をそのまま書くと、「その文字列そのものだけ」を許す型になります。{ kind: "select" } は「kind が "select" という文字列であるもの」だけです。

L23-27 はこの 2 つを組み合わせ、「4 つの形のうちどれか 1 つ」を表しています。

ts type Screen = | { kind: "select" } // 選曲: 追加の値なし | { kind: "play"; songId: string; difficulty: …; … } // プレイ: 曲と難易度 | …

先頭の | は飛ばして読んで構いません（並びをそろえるために置いてあります）。{ } の中の ; は項目の区切りです。

このように「共通の kind で、どの形かを見分けられる」合併型を使うと、if (screen.kind === "play") や switch (screen.kind) で場合を分けた先で、TypeScript がその形の項目（songId など）だけを使えるようにしてくれます（L77-122）。kind が "select" の値から songId を読もうとすると、書いた時点でエラーになります。

各項目の前の readonly は「作った後に書き換えない」印です（文法の索引の『interface と readonly』）。画面の値は書き換えず、移るときは新しい値を丸ごと作って setScreen に渡します。

文法: 関数コンポーネントと props

React では、画面の部品（コンポーネント）を「受け取った値から、描くべき JSX を返す関数」として書きます。名前は大文字で始めます（JSX で <App /> と書いたときに、HTML のタグと区別するため）。

tsx export function App() { … return <SongSelect songs={songs} … />; }

部品に渡す値を props（properties の略）と呼びます。L82 の songId={screen.songId} は、Play という部品に songId という名前で値を渡しています。受け取る側の src/ui/Play.tsx は L26 で

tsx export function Play({ songId, difficulty, settings, onFinish, onRetry, onQuit }: Props) {

と、渡された props を 1 つの入れ物として受け取り、中身を名前ごとに取り出しています（取り出し方は下の『分割代入』）。App は誰からも props を受け取らないので () が空です。

props は親から子への一方通行です。子が親の値を変えたいときは、親が渡しておいた関数（onFinish や onSelect など、on で始まる名前にする習慣があります）を呼んで頼みます。

React はこの関数を何度も呼び直します。覚えている値（下の useState）が変わるたびに関数をもう一度呼び、返ってきた JSX を前回と比べて、違う所だけページを書き換えます。これを「描き直し（再レンダー）」と呼びます。ですから関数の中の const は描き直しのたびに作り直されます。

文法: useState

関数は呼ぶたびに最初から実行されるので、普通の変数では前回の値を覚えておけません。useState は「React に値を預けておき、描き直しのたびに最新の値を返してもらう」ための関数です（use で始まる React の関数を「フック」と呼びます）。

tsx const [screen, setScreen] = useState<Screen>({ kind: "select" });

  • 引数 { kind: "select" } は最初の 1 回だけ使う初期値です。
  • 返ってくるのは 2 つ組で、1 つ目 screen がいまの値、2 つ目 setScreen が値を変える関数です。
  • setScreen(新しい値) を呼ぶと、React が値を入れ替えて App を描き直します。screen = … と直接代入しても React は気づかず、画面は変わりません。
  • setScreen((prev) => 新しい値) と関数を渡すと、「直前の値 prev から新しい値を作る」という頼み方になります（L50, L62）。
  • 初期値の代わりに関数を渡すと（L32 の useState<Settings>(loadSettings)）、React は最初の 1 回だけその関数を呼んで、戻り値を初期値にします。useState(loadSettings()) と書くと、描き直しのたびに loadSettings() が呼ばれて（結果は捨てられて）しまいます。

文法: 分割代入

配列やオブジェクトの中身を、1 文で複数の変数に取り出す書き方です。

ts const [songs, setSongs] = useState(…); // 配列の 0 番目を songs、1 番目を setSongs に const { ctx } = audioKit(); // オブジェクトの ctx という項目を ctx に

配列は [ ] で位置で取り出し、名前は自由に付けられます。オブジェクトは { } で項目の名前で取り出し、同じ名前の変数になります（src/ui/Calibrate.tsx の L42）。

関数の引数の位置にも書けます。function Result({ song, difficulty, … }: Props)（src/ui/Result.tsx の L24）は、「1 つ目の引数として受け取ったオブジェクトから song や difficulty を取り出す」という意味です。React の部品の props の受け取りはほとんどこの形です。{ song, large = false }（src/ui/SongSelect.tsx の L27）のように = 値 を添えると、その項目が無いときの既定値になります。

文法: ジェネリクス（型引数 <T>）

useState<Settings>(…) の <Settings> は、関数に渡す「型の引数」です。useState はどんな種類の値でも預かれるように作られていて、< > で「今回は Settings 型の値を預ける」と指定します。指定すると、返ってくる値も Settings 型、setSettings に渡せるのも Settings 型だけになります。

型の引数を受け取れる関数や型をジェネリクスと呼びます。初期値から型が分かるときは省略できますが、L30 のように初期値が null だと「null しか入らない」と推し量られてしまうので、<readonly SongSummary[] | null>（「SongSummary の読み取り専用の配列か、null」）と明示しています。

T[] は「T の配列」という型で、前に readonly を付けると「要素を足したり書き換えたりしない配列」になります。

文法: アロー関数

(引数) => 式 または (引数) => { 文…} は、名前の無い関数をその場で作る書き方です。

ts (e: unknown) => setError(…) // e を受け取り、setError(…) の結果を返す関数 () => { loadIndex()…; } // 引数なし。{ } の中の文を実行する関数

  • => の右が { } でなければ、その式の値がそのまま戻り値になります（return を書かない）。{ } で囲んだら、値を返すには return が要ります。
  • 引数が無ければ ()、1 つなら (x)、複数なら (a, b) です。型注釈を付けるときは (e: unknown) のように書きます。
  • 変数に入れれば普通の関数と同じように呼べます（const toSelect = … () => …;、L75）。
  • function f() { … } との違いのうち、このコードで効くのは「その場で書ける短さ」だけです。React のコードでは、部品に渡す関数や、他の関数の引数として渡す関数の多くをアロー関数で書きます。

文法: useEffect

部品を描いた後に、画面の外とのやり取り（ファイルの読み込み、キー入力の受け付け、保存など）をするための関数です。

tsx useEffect(() => { やりたい処理 return () => { 後片付け }; // 省略可 }, [見張る値1, 見張る値2]);

  • 第 1 引数の関数は、描き終えた後に React が呼びます。
  • 第 2 引数の配列（依存配列）に書いた値が、前回の描画から変わったときだけ、もう一度呼びます。L42 のように空の配列 [] なら、部品が画面に出たときの 1 回だけです。配列ごと省略すると、描き直しのたびに毎回呼ばれます。
  • 第 1 引数の関数が関数を返すと、それは「後片付け」として、次に呼び直す前と、部品が画面から消えるときに呼ばれます。キー入力の受け付けを止めるのに使います（src/ui/SongSelect.tsx の L62）。
  • StrictMode（src/main.tsx の L10）の下では、開発中だけ「1 回目 → 後片付け → 2 回目」と余分に走ります。後片付けを正しく書いていれば、結果は 1 回のときと同じになります。

部品の関数の本体に直接書かないのは、本体は描き直しのたびに何度も呼ばれるからです。本体に loadIndex() を書くと、描き直すたびに読み込みが走ります。

loadIndex() は曲の一覧をネットワークから読み込む関数で（src/song/load.ts の L12）、すぐには結果を返さず「後で結果が届く約束」（Promise）を返します（文法の索引の『async / await と Promise』）。L40-41 はその約束に、届いたときの処理をつないでいます。

  1. .then(setSongs) — 一覧が届いたら、それを setSongs に渡す。setSongs を呼ぶと songs が入り、App が描き直されて一覧が出る。.then((list) => setSongs(list)) と同じことを、関数そのものを渡して短く書いている
  2. .catch((e: unknown) => …) — 途中で失敗したら（ファイルが無い、形式が違うなど）、失敗の理由 e を受け取って setError に入れる

文法: instanceof

値 instanceof Error は、「その値が Error の仲間として作られた物か」を真偽で返します。throw で投げられるものは何でもよいので（文字列でも数でも）、.catch で受け取った e が本当にエラーかは分かりません。そのため TypeScript は e を unknown（「何か分からない値」。確かめるまで中身を使えない型）にしておき、instanceof Error で確かめてから e.message（エラーの説明文）を読みます。

文法: 条件演算子 ? :

条件 ? A : B は、条件が真なら A、偽なら B になる式です。if 文と違い、値を返すので代入や引数の中に書けます。L41 は「e がエラーならその説明文、そうでなければ決まった文」を setError に渡しています。

失敗したときは songs が null のまま error に文が入ります。選曲画面（src/ui/SongSelect.tsx の L90-91）は error があればそれを出し、songs も error も無い間は「読み込み中…」を出します。

[] を渡しているので、起動して最初に描いたときの 1 回だけ読み込みます（開発中は StrictMode によって 2 回読み込みますが、後から届いたほうで上書きされるだけです）。

文法: オプショナルチェーン ?. と ??

  • a?.b は「a が null か undefined なら、そこで止めて undefined を返す。そうでなければ a.b」です。a.b と書くと、a が null のときにエラーで止まります。
  • a?.[0] は配列の添字版、a?.(…) は関数呼び出し版です。
  • a ?? b は「a が null か undefined なら b、そうでなければ a」です。「値が無いときの代わり」を書くのに使います。a || b と似ていますが、|| は 0 や空文字 "" も「無い」とみなして b にしてしまうのに対し、?? は null と undefined だけを置き換えます。

undefined は null とは別の「値が無い」で、配列の範囲外を読んだときや、オブジェクトに無い項目を読んだときに返ってきます。

文法: 厳密な比較 === と !==

JavaScript の等しいかどうかの比較は ===（等しくないは !==）を使います。== もありますが、"1" == 1 が真になるなど、型の違う値を勝手に変換してから比べるため、このコードでは使っていません。

L45 は「選曲画面でどの曲を選んだ状態にするか」を決めます。分解すると次のとおりです。

  1. songs?.some((s) => s.id === selection.songId) — 曲の一覧のうち 1 曲でも、ID が前回選んだ曲の ID と同じものがあるか。.some(関数) は配列の要素を順に関数に渡し、1 つでも真を返せば真になります。songs が null（読み込み中）なら ?. で止まって undefined（偽とみなされる）
  2. 真なら、前回選んだ曲 selection.songId をそのまま使う
  3. 偽なら songs?.[0]?.id ?? null — 一覧の先頭の曲の ID。一覧が null か空なら null

コメント（L44）のとおり、初めて遊ぶ人（前回の曲が null）や、曲の入れ替えで前回の曲が一覧から消えた場合に、先頭の曲を選んだ状態で始めるためです。selectedId は useState ではなく、描き直しのたびに songs と selection から計算し直す値です。

文法: useCallback

部品の中で作った関数は、描き直しのたびに新しく作られます。中身が同じでも、前回の関数とは別物として扱われます。

useCallback(関数, [依存配列]) は、依存配列の値が変わらない間、前回と同じ関数を返し続けるフックです。L49-51 は [] なので、updateSelection はずっと同じ 1 つの関数です。

これが効くのは、関数を子の部品に渡し、子が useEffect の依存配列にその関数を入れているときです。src/ui/SongSelect.tsx の L63 は依存配列に onSelect などを入れているので、毎回新しい関数が来ると、描き直しのたびにキー入力の受け付けを外して付け直すことになります。

文法: スプレッド構文 ...

オブジェクトの前に ... を付けて { } の中に書くと、その中身の項目を全部その場に並べたことになります。

ts const prev = { songId: "fur-elise", difficulty: "normal" }; const patch = { difficulty: "hard" }; ({ ...prev, ...patch }) // → { songId: "fur-elise", difficulty: "hard" }

同じ名前の項目は後に書いたほうが勝ちます。これで「prev を写した新しいオブジェクトを作り、patch にある項目だけ上書きする」ができます。元の prev は変わりません。配列にも使え、[...values] は配列の写しを作ります（src/game/stats.ts の L3）。

React では useState の値を直接書き換えず、このように新しいオブジェクトを作って set… に渡します。React は「前と別のオブジェクトか」で変化を見分けるので、中身だけ書き換えると変化に気づかず、画面が変わりません。

文法: Partial（全部を省略可能にした型）

Partial<LastSelection> は「LastSelection の項目を、どれも省略してよいことにした型」です。LastSelection は songId と difficulty の 2 つを必ず持ちますが（src/storage.ts の L99-102）、Partial<LastSelection> なら { songId: "x" } だけ、{ difficulty: "hard" } だけ、でも受け付けます。< > の中に型を渡して別の型を作る、型のジェネリクスです。

文法: プロパティの省略記法

{ songId } は { songId: songId } の省略です。項目名と、値を入れた変数の名前が同じときに使えます。L52 は「songId という項目に、引数の songId を入れたオブジェクト」を updateSelection に渡しています。

L49-53 は選んだ曲・難易度を変えるための関数です。

文法: switch による場合分け

switch (値) { case A: … case B: … default: … } は、値が A なら case A: の後ろから、B なら case B: の後ろから実行する書き方です。どれにも当たらなければ default: の後ろへ行きます。

普通は case の終わりに break; を書いて抜けますが、ここでは各 case が return で関数そのものを抜けるので break が要りません。return も break も無いと次の case の中身まで続けて実行してしまうので、このプロジェクトでは型の検査の設定（tsconfig.json の noFallthroughCasesInSwitch）でそれを禁じています。

合併型の kind で switch すると、case "play": の中では screen が "play" の形に絞られ、screen.songId を読めます。

文法: テンプレート文字列

` （バッククォート）で囲んだ文字列の中に ${式} と書くと、その式の値が文字列に埋め込まれます。

ts `${screen.songId}:${screen.difficulty}:${screen.attempt}` // → "fur-elise:hard:2"

screen.songId + ":" + screen.difficulty + … と + でつなぐのと同じ結果になります。JSX の属性に書くときは { } で囲みます。

文法: key（部品の見分け札）

key は React が特別に扱う props で、部品には渡されません。React は描き直しのとき、前回と同じ場所に同じ種類の部品があれば「同じ部品の続き」とみなし、useState などで覚えた値を引き継ぎます。key が前回と違えば「別の部品」とみなし、古いほうを捨てて新しく作ります。配列から並べて描くときにも、どの要素がどれかを見分けるために使います（src/ui/SongSelect.tsx の L97）。

プレイ中に R キーでやり直すと（src/ui/Play.tsx の L131）、play が呼ばれて画面は "play" のまま attempt だけが 1 増えます（L62）。key に attempt が入っているので、key が変わり、React はプレイ画面を捨てて作り直します。プレイ画面が覚えていた途中のスコアや音の予約は、作り直しで全部消えて最初からになります。key が同じままだと、同じ部品の続きとして扱われ、進行中の状態が残ってしまいます。
