src/ui/Calibrate.tsx

takumayellow/syncadence-v2 の main（eb9c698）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

0.6 秒おきに 20 回鳴るクリック音に合わせてキーか画面を叩いてもらい、音が聞こえてから押すまでのずれの中央値を測って「入力の補正」に入れる、タイミング調整の画面の部品です。

このファイルが担うもの

  • クリック音を Web Audio（ブラウザの音を作る仕組み）で 20 回、あらかじめ予約して鳴らす（L22-32、L45）。
  • 叩いた時刻を、「最初のクリックが聞こえた時刻から何ミリ秒後か」として集める（L61-68）。
  • 最後のクリックの 1 秒後に集計し、最初の 4 回を除いたクリックとのずれの中央値を出す（L52-59）。
  • 測れたら、その値を入力の補正に置き換えて選曲に戻るボタンを出す（L113-120）。

画面は 3 つの段階（Phase）を行き来します。

段階 画面 次へ
idle 説明と「始める」 「始める」で running
running 叩いた回数 13 秒後に done
done 測った値と「入力の補正を〜にして戻る」、または「測れませんでした」 「もう一度測る」で running

L22–L33

click(ctx, when, accent) は、クリック音を 1 つ、時刻 when（AudioContext の時計で秒）に鳴るよう予約します。

Web Audio では、音を作る部品（ノード）を線でつないで、最後に出口（ctx.destination、スピーカー）へ流します。ここでは 2 つのノードを使います。

ノード 作る行 役目
OscillatorNode（osc） L23 決まった高さの音を出し続ける発振器
GainNode（gain） L24 通る音の大きさを変える
  1. L25 — 音の高さ。accent なら 1760 Hz、そうでなければ 1320 Hz。L45 で 4 回に 1 回（1・5・9・13・17 回目）を accent にするので、4 拍ごとに 1 回だけ高い音になります
  2. L26-28 — 音の大きさの時間変化を予約する。when に 0.0001（ほぼ無音）、2 ミリ秒後に 0.5、60 ミリ秒後に 0.0001 まで、指数的に（同じ時間ごとに同じ割合で）変える。急に立ち上がって、すっと消える「コッ」という音になる
  3. L29 — 発振器 → 音量 → 出口の順につなぐ。connect はつないだ先のノードを返すので、.connect(…).connect(…) と続けて書ける
  4. L30-31 — when に鳴らし始め、80 ミリ秒後に止める

大きさを 0 ではなく 0.0001 にしているのは、指数的な変化（exponentialRampToValueAtTime）では 0 を始まりにも終わりにもできないからです。0 から何倍しても 0 のままなので、0 へ向かう指数的な変化は計算できません。

すべて時刻を指定した予約なので、JavaScript の処理が少し遅れても、音は AudioContext の時計どおりに鳴ります。

22function click(ctx: AudioContext, when: number, accent: boolean): void {
23 const osc = ctx.createOscillator();
24 const gain = ctx.createGain();
25 osc.frequency.value = accent ? 1760 : 1320;
26 gain.gain.setValueAtTime(0.0001, when);
27 gain.gain.exponentialRampToValueAtTime(0.5, when + 0.002);
28 gain.gain.exponentialRampToValueAtTime(0.0001, when + 0.06);
29 osc.connect(gain).connect(ctx.destination);
30 osc.start(when);
31 osc.stop(when + 0.08);
32}

L41–L51

文法: setTimeout と clearTimeout

window.setTimeout(関数, ミリ秒) は、「このミリ秒が経ったら、この関数を 1 回呼んで」とブラウザに予約します。予約するとすぐに次の行へ進み、待っている間もほかの処理は動きます。

戻り値は予約の番号です。この番号を window.clearTimeout(番号) に渡すと、まだ呼ばれていない予約を取り消せます。

時間はおおよそで、ブラウザが忙しいと遅れます。正確な時刻が要る音は、L22-32 のように AudioContext の予約で鳴らします。

start は「始める」を押したときに呼ばれ、測り始めます。async が付いているので、途中の await で待つことができます（文法の索引の『async / await と Promise』）。

  1. L42 — ゲーム全体で 1 つの AudioContext を受け取る。まだ無ければここで作られる（src/audio/context.ts の L11-17）
  2. L43 — ctx.resume() で音を出せる状態にし、それが終わるまで待つ。ブラウザは、利用者がページを操作するまで音を出させないので、ボタンを押した流れの中で呼ぶ
  3. L44 — 最初のクリックの時刻 begin を、今から 0.6 秒後にする。予約を並べ終える前に時刻が過ぎてしまわないための余裕
  4. L45 — 20 回のクリックを予約する。i 回目（0 から数える）は begin + i × 0.6 秒。i % 4 === 0 は「i を 4 で割った余りが 0」で、i が 0・4・8・12・16 のとき高い音にする
  5. L46 — begin を曲の 0 秒とする時計を作る（SongClock、文法の索引の『class と constructor』）。最後の 1 は再生速度で、時計がそのままの速さで進む
  6. L47 — 集計の予約。600 + 20 × 600 + 400 = 13000 ミリ秒後に finish を呼ぶ。最後のクリックは押してから 0.6 + 11.4 = 12.0 秒後なので、その 1.0 秒後に締め切る
  7. L48 — 記録を run.current に入れる。taps: [] は空の配列から始めるということ
  8. L49 — 段階を running にして、画面を描き直す

SongClock は、プレイ画面でも使う「いま聞こえている音は、曲の何秒目か」を出す時計です（src/audio/clock.ts の L30-68）。スピーカーやイヤホンまでの遅れをブラウザが申告していれば、その分を差し引きます。L94 の説明文の「自動で差し引いている」はこのことです。

L52–L60

文法: Array.from で番号から配列を作る

Array.from({ length: n }, (_, i) => 式) は、長さ n の配列を作り、i 番目（0 から）の要素を 式 で決めます。for で空の配列に 1 つずつ足すのと同じ結果を、1 つの式で作れます。

2 つ目の引数の関数は「要素」と「番号」の 2 つを受け取りますが、ここでは要素（中身は空）を使わないので、名前を _ にしています。_ は「使わない」の印として慣習的に使う名前で、特別な意味はありません。

finish は、L47 の予約から 13 秒後に呼ばれ、集計します。

  1. L53-54 — 記録が無ければ（もう集計した、画面を離れた、など）何もしない
  2. L55 — 数える拍の時刻（ミリ秒）の表を作る
  3. L56 — 叩いた時刻と拍の時刻の表から、ずれの中央値を出す
  4. L57 — 記録を消す。これ以降の叩きは L63 で無視される
  5. L58 — 段階を done にして結果を出す

L55 の表は、i が 0〜15 の 16 個で、(i + 4) × 600 です。

i 0 1 2 … 15
時刻（ミリ秒） 2400 3000 3600 … 11400
何回目のクリックか 5 6 7 … 20

L66 で叩いた時刻を「最初のクリックが聞こえてから何ミリ秒後か」で記録しているので、この表と直接比べられます。

calibrate（src/game/stats.ts の L29-39）は、叩いた時刻の 1 つずつについて、表のうち最も近い拍を探し、その差が半拍（300 ミリ秒）未満なら「ずれ」として残します。ずれが 4 個以上あればその中央値を、足りなければ null を返します。

最初の 4 回の叩きは、この仕組みで自然に捨てられます。4 回目のクリック（1800 ミリ秒）にぴったり叩いても、表で一番近いのは 2400 ミリ秒で、差が 600 ミリ秒あるからです。1 回目から 4 回目の近くの叩きを捨てるための特別な処理は書かれていません。

平均ではなく中央値を使うのは、叩き損ねや 2 度叩きのような大きく外れた数回に、結果が引っ張られないためです。

イベントに付いた時刻を使うのは、処理が始まるまでの数ミリ秒の遅れを測定に混ぜないためです。

この記録は、入力の補正を引く前の生の時刻です。だから L115 では、測ったずれをそのまま補正の値にします。プレイ中のずれ（補正を引いた後の残り）から提案する結果画面は、今の補正に足します（src/ui/Result.tsx の L74）。

run を useRef にしている理由: L70-85 のキーの受け付けは、画面を開いたときに 1 回付けたきりで、そのとき作られた tap を呼び続けます。tap が useState の値を読んでいたら、ずっと「開いたときの値」を読むことになります。run は描き直しても同じ入れ物なので、古い tap からでも run.current で最新の記録に届きます。L47 の予約が 13 秒後に呼ぶ finish も同じです。
