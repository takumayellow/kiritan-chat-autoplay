src/game/judge.ts

takumayellow/syncadence-v2 の main（eb9c698）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

押した時刻のずれ（ミリ秒）を PERFECT・GREAT・GOOD・MISS のどれかに決める「判定幅」と、判定ごとのスコアの重みを決めておくファイルです。

このファイルが担うもの

  • 判定の 4 つの名前（Judgement、L1）と、その並び順（JUDGEMENTS、L3）。
  • 判定幅 WINDOWS（L6-11）。PERFECT ±42 ms、GREAT ±83 ms、GOOD ±125 ms、MISS ±160 ms。
  • ロングノーツを離すときの猶予 HOLD_RELEASE_TOLERANCE_MS（L14）。150 ms。
  • スコアの重み SCORE_WEIGHT と満点 MAX_SCORE（L16-17）。
  • ずれから判定を 1 つ決める関数 judgeDelta（L20-27）。

どのノーツに当てるか、ロングノーツをどう数えるかは src/game/session.ts が決めます。このファイルは数を決めておくだけで、状態を持ちません。

向き 相手 何のために
呼ばれる src/game/session.ts（L2 で取り込み） judgeDelta で押下を判定し（L100）、WINDOWS.good で見逃しを決め（L148）、離しの猶予（L119）・重み（L79）・満点（L170）を使う

呼ばれる src/render/highway.ts（L1 で取り込み、L373・L383） MAX_SCORE で割って、スコアのゲージの長さを決める

読みどころ

  • judgeDelta（L20-27）。ずれの絶対値を、狭い幅から順に比べるだけの短い関数です。
  • WINDOWS の 4 つの数と SCORE_WEIGHT の 4 つの数が、ゲームの手応えのほぼ全部を決めています。docs/design.md の 6 節に同じ表があります。

落とし穴

  • 幅は実時間のミリ秒です。 曲の時間差のまま渡すと、テンポを落としたときに幅が狭く感じられます。曲の秒から実時間のミリ秒への換算は、呼び出し側の session.ts の realMs（L72-74）がしています。
  • 早すぎても遅すぎても、絶対値で同じ幅です（L21）。ただし遅い側は、session.ts の update が 125 ms を過ぎたノーツを先に見逃しの MISS にするので、125〜160 ms 遅れの MISS はめったに出ません（session.ts の解説の「落とし穴」）。
  • breaksCombo（L29-31）は、このコミットではどこからも呼ばれていません。コンボを切る条件は session.ts の L80 に直接書かれています。

L1–L2

Judgement は、判定の 4 つの名前のどれか 1 つを表す型です（文法の索引の『型の別名 type と合併型 |』）。"perfect" などの文字列そのものを型にしているので、"Perfect" のような書き間違いは TypeScript が見つけてくれます。

画面に出す "PERFECT" などの大文字の表記は、使う側（src/ui/Result.tsx の L21 など）がこの名前から引いて決めます。

1export type Judgement = "perfect" | "great" | "good" | "miss";

L3–L4

JUDGEMENTS は 4 つの判定を、良い順に並べた配列です。型 readonly Judgement[] は「Judgement の配列で、要素を足したり書き換えたりできない」という意味です（readonly は文法の索引の『interface と readonly』）。

結果画面（src/ui/Result.tsx の L51）が、この順に「PERFECT が何個、GREAT が何個…」の行を並べるのに使います。合併型の Judgement は型なので実行時には消えてしまい、並び順を取り出せません。そこで、実行時にも残る値として同じ 4 つを配列で持っています。

3export const JUDGEMENTS: readonly Judgement[] = ["perfect", "great", "good", "miss"];
4 

L5–L12

判定幅です。押した時刻とノーツの時刻の差の絶対値（早くても遅くても正の数にしたもの）が、

差の絶対値 判定
42 ms 以下 PERFECT
42 ms より大きく 83 ms 以下 GREAT
83 ms より大きく 125 ms 以下 GOOD
125 ms より大きく 160 ms 以下 MISS
160 ms より大きい 判定しない（空振り）

になります。比べ方は L22-26 の <=（以下）なので、ちょうど 42 ms は PERFECT です。

60 フレーム毎秒の画面では 1 フレームが約 16.7 ms なので、PERFECT の幅 ±42 ms は前後それぞれ約 2.5 フレーム分です。

最後の as const（文法の索引の『as const と配列の要素の型』）は、オブジェクトの欄を読み取り専用にし、perfect の型を「数」ではなく「ちょうど 42」にします。うっかり WINDOWS.good = 200 と書き換えると TypeScript がエラーにします。

L5 のコメントにある「これより外の早押しは空振りとして無視する」は、MISS の幅（160 ms）より早い押下を判定に数えない、という意味です。ノーツが来るかなり前に押してしまっても、MISS を付けてノーツを消費することはなく、ノーツはそのまま残ります。

5/** 判定幅（実時間ミリ秒、±）。これより外の早押しは空振りとして無視する。 */
6export const WINDOWS = {
7 perfect: 42,
8 great: 83,
9 good: 125,
10 miss: 160,
11} as const;

L16–L18

文法: 数の区切り _

1_000_000 は 1000000（百万）と同じ数です。数字の間の _ は読みやすくするための区切りで、値には影響しません。日本語で「1,000,000」とカンマを入れるのと同じ使い方です（プログラムではカンマは別の意味になるので _ を使います）。

SCORE_WEIGHT は、判定 1 つで得る点の重みです。型 Record<Judgement, number>（文法の索引の『Record 型』）は「4 つの判定の名前を全部、欄として持ち、どれも数」という意味で、どれか 1 つでも書き忘れるとエラーになります。

MAX_SCORE は満点です。session.ts の currentScore（L169-171）は、

スコア = 重みの合計 ÷ 判定の総数 × 1,000,000

で計算します。全部 PERFECT なら 1,000,000、全部 GREAT なら 750,000、全部 GOOD なら 350,000 です。ロングノーツの終点は PERFECT（重み 1）か MISS（重み 0）にしかならないので、押し切れば必ず満点の分を取れます。

ランク（SSS は 990,000 以上など）は、この数をもとに src/game/rank.ts が決めます。

16export const SCORE_WEIGHT: Record<Judgement, number> = { perfect: 1, great: 0.75, good: 0.35, miss: 0 };
17export const MAX_SCORE = 1_000_000;
18 

L19–L28

judgeDelta(deltaMs) は、押した時刻の差（実時間ミリ秒）から判定を 1 つ返します。戻り値の型 Judgement | null は「判定か、判定しないことを表す null」です。

  1. L21 Math.abs(deltaMs) で絶対値を取る。-30（30 ms 早い）も 30（30 ms 遅い）も 30 として扱います。
  2. L22-25 狭い幅から順に比べ、最初に収まった判定を返す。return した時点で関数は終わるので、例えば 30 は L22 で "perfect" を返し、L23 以降は見ません。
  3. L26 どれにも収まらなければ null。

狭い順に並べてあるので、L23 の GREAT の条件は「83 以下」と書くだけで、実際には「42 より大きく 83 以下」の意味になります。

例えば再生速度 1 で、ノーツより 0.06 秒遅く押した場合、差は 60 ms なので GREAT です。再生速度 0.5 で曲の時間で 0.03 秒遅く押した場合も、session.ts が実時間の 60 ms に直してから渡すので、同じく GREAT になります。

19/** 押した時刻の差（実時間ミリ秒、正なら遅い）から判定する。判定の外なら null。 */
20export function judgeDelta(deltaMs: number): Judgement | null {
21 const d = Math.abs(deltaMs);
22 if (d <= WINDOWS.perfect) return "perfect";
23 if (d <= WINDOWS.great) return "great";
24 if (d <= WINDOWS.good) return "good";
25 if (d <= WINDOWS.miss) return "miss";
26 return null;
27}
