L1–L4

文法: import と export

JavaScript や TypeScript では、1 つのファイルが 1 つの「モジュール（部品の入れ物）」です。ほかのファイルから使ってほしいものには、定義の前に export を付けておきます（例: src/ui/App.tsx の L28 export function App() { … }）。使う側は import で取り込みます。

ts import { StrictMode } from "react"; // react という入れ物から StrictMode だけを取り出す import { App } from "./ui/App"; // このファイルから見て ./ui/App.tsx にある App を取り出す import "./styles/index.css"; // 中身を名前で受け取らず、読み込むことだけをする

  • { } の中には、相手が export した名前を書きます。名前が違えば変換の時点でエラーになります。{ a, b, c } のようにカンマで並べて複数取り出せます。
  • from の後ろの文字列は「どこから」です。"react" のように . で始まらないものは、npm install で入れたライブラリ（node_modules/ の中）を指します。"./ui/App" のように ./（同じフォルダ）や ../（1 つ上のフォルダ）で始まるものは、このファイルからの相対的な位置です。拡張子 .tsx / .ts は省略できます。
  • import type { 名前 } や { type 名前 } と書くと、「型（値の形の決まりごと）だけを取り込み、実行するプログラムには何も残さない」という意味になります（src/ui/App.tsx の L2・L4 で出てきます）。
  • export の前に default が付く書き方もありますが、このゲームのコードでは使っていません。すべて名前付きで export し、名前付きで import しています。

L1-3 は 3 つの部品を取り込みます。

  • StrictMode（L1）: React 本体に入っている「点検用の囲い」。L9 で使います。
  • createRoot（L2）: react-dom は React の部品をブラウザのページ（DOM）に描くための別のライブラリです。/client は「ブラウザの中で動かす用」の入口を指します。
  • App（L3）: このゲームの画面全体。src/ui/App.tsx の L28 で export されています。

L4 は CSS ファイルを読み込むだけの import です。JavaScript の普通の機能としては CSS を取り込めませんが、Vite がこの書き方を「このページに CSS を足す」と解釈して処理します。名前を受け取らないので { } も from もありません。CSS はページ全体に効くので、最初に 1 回読み込めば、どの画面の部品にも効きます。

1import { StrictMode } from "react";
2import { createRoot } from "react-dom/client";
3import { App } from "./ui/App";
4import "./styles/index.css";

L5–L7

文法: const と let

const 名前 = 値; は変数を作る書き方で、あとから別の値を入れ直せない変数になります。入れ直したい変数は let で作ります（src/ui/select.ts の L5 let hash = 0;）。このゲームのコードは、ほとんどの変数を const で作っています。値が途中で変わらないと分かっていれば、読むときに「この名前はずっと同じものを指す」と安心して追えるからです。

文の終わりの ; は省略しても動くことが多いのですが、このコードでは必ず付けています。

文法: 非 null 表明 !

! は置く場所で意味がまったく違います。

  • 前に置く !x は「否定」です。x が「無い」とみなされる値（null、undefined、false、0、空文字 ""）なら真になります。L7 の !root はこちらで、「root が見つからなかったら」と読みます。
  • 後ろに置く x! は TypeScript だけの書き方で、非 null 表明と呼びます。「この値は null や undefined ではないと私が保証する」と型の検査に伝え、検査を黙らせます。実行時には何もしません。たとえば src/game/stats.ts の L5 sorted[mid]! は「配列のこの位置には必ず数が入っている」と書き手が請け合っています。

後ろの ! は保証が外れていても止まらずに進んでしまうので、L6-7 のように本当に確かめて止めるほうが安全です。L6 を document.getElementById("root")! と書けば L7 は要らなくなりますが、index.html から <div id="root"> が消えたときに、原因の分かりにくいエラーが別の場所で出ることになります。

文法: 例外を投げる throw

throw new Error("説明"); は、その場で処理を打ち切って「失敗した」と知らせる書き方です。new Error(…) で失敗の説明を持った物（エラーオブジェクト）を作り、throw で投げます。投げられたエラーは、受け止める仕組み（try / catch、src/storage.ts で説明）が無ければ、そこで実行が止まり、ブラウザの開発者ツールにメッセージが出ます。

L6 の document は、ブラウザが用意している「いま開いているページそのもの」を表す物です。ページの HTML はブラウザの中で要素の木（DOM と呼びます）になっていて、document.getElementById("root") はその木から id="root" の要素を 1 つ探して返します。見つからなければ null（「何も無い」を表す値）が返ります。

探している要素は index.html の <div id="root"></div> です。中身が空の箱で、L8 以降で React がこの中に画面を描きます。

TypeScript は、getElementById の結果が「HTML の要素か null のどちらか」だと知っています。L7 の if で null の場合を throw で抜けさせると、L8 の時点では root が null ではないと TypeScript が理解し、createRoot(root) を許します。このように、if で場合を絞ると型も絞られる仕組みを型の絞り込みと呼びます。

5 
6const root = document.getElementById("root");
7if (!root) throw new Error("#root がありません");

L8–L12

文法: JSX

<StrictMode> や <App /> のように、JavaScript の式の中に HTML に似たタグを書く書き方を JSX と呼びます。ファイルの拡張子が .tsx（JavaScript なら .jsx）のときだけ書けます。見た目は HTML ですが文字列ではなく、変換すると関数呼び出しになります。

tsx <StrictMode> <App /> </StrictMode>

は、おおよそ次のように変換されます。

ts jsx(StrictMode, { children: jsx(App, {}) })

読み方の決まり:

  • 先頭が小文字のタグ（<div>、<button>、<p>）は HTML の本物の要素になります。先頭が大文字のタグ（<App>、<StrictMode>）は、自分たちや React が作った「部品（コンポーネント）」を使う、という意味です。
  • <App /> のように /> で閉じるのは「中身の無いタグ」です。中身があるときは <StrictMode> … </StrictMode> と開きと閉じで挟みます。挟んだ中身は、部品の側からは children という名前で受け取れます。
  • タグには 名前={値} の形で値を渡せます（src/ui/App.tsx の L80 songId={screen.songId}）。{ } の中には JavaScript の式を何でも書けます。文字列なら className="song-row" のように " " だけでも書けます。
  • HTML の class は、JavaScript の予約語と重なるので JSX では className と書きます。onclick は onClick のように単語の区切りを大文字にします。
  • 全体を ( ) で囲むのは、複数行にまたがる JSX を 1 つの式として扱わせるためです（src/ui/App.tsx の L77-87）。

部品の作り方と値の受け取り方は src/ui/App.tsx の「関数コンポーネントと props」で説明します。

L8 は 2 段で読みます。

  1. createRoot(root) — L6 で見つけた <div id="root"> を受け持つ「描画係」を作る
  2. .render( … ) — その描画係に「この部品の木を描いて」と頼む

StrictMode は開発中（npm run dev で動かしているとき）だけ働く点検用の囲いで、画面には何も出しません。部品を作るときの処理や、useEffect（src/ui/App.tsx で説明）の処理をわざと 2 回走らせ、「2 回走ると壊れる書き方」を早く見つけられるようにします。公開した版（npm run build で作ったもの）では 2 回走りません。
