tools/fetch_sources.py

takumayellow/syncadence-v2 の main（eb9c698）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

Mutopia Project から曲ごとの楽譜（LilyPond の .ly）と MIDI を取ってきて、楽譜のヘッダに「Public Domain」と書かれていない曲を止める、取り込みの入口のファイルです。

このファイルが担うもの

  • 曲の目録 tools/songs.json を読み、曲 ID と Mutopia 上のパスが安全な文字だけでできているかを確かめる（load_catalog、L32-39）。
  • Mutopia の配布サーバ（https://www.mutopiaproject.org/ftp/）からだけ .ly と .mid を取る（download、L42-47 と fetch_song の L60-64）。
  • .ly のヘッダに license = "Public Domain" か copyright = "Public Domain" があるかを確かめ、無ければ例外で止める（L66-68）。
  • 出どころの URL、浄書者、底本、ファイルの SHA-256、確認日を sources/mutopia/<曲ID>/meta.json に書く（L70-87）。

ここで取ったファイルを、tools/build_songs.py が譜面と音のデータに変えます。手で 1 回動かす道具で、ゲームの実行中には動きません。

なぜ Mutopia の Public Domain の楽譜だけを使うのか

曲の権利は層に分かれています（docs/research/04-assets-and-licenses.md の 1 節）。

層 このゲームでの扱い
作曲 作曲者の死後 70 年で切れる。収録曲の作曲者で最も遅いサティ（1925 年没）でも切れている
楽譜データ（浄書・入力した人の仕事） ここを確かめる必要がある。 このファイルの検査はこの層のためのもの
録音・演奏 使わない。音は楽譜から合成する
ピアノの音源 CC0 の FreePats を使う（tools/build_samples.py）

Mutopia の楽譜は曲ごとにライセンスが違い、Public Domain のほかに CC 系（表示や継承の条件が付くもの）もあります。Public Domain だけに絞れば、楽譜から作った譜面や曲データに条件が付かず、「権利の確認が楽譜の版だけで済む」（docs/design.md の 1 節）。※ 推測: CC 系を受け入れると、条件の確認と表示を曲ごとに管理する手間が増えるので、最初から入口で断る形にしたと考えられます。

この検査は通らなければ止まる側に倒してあります。ヘッダが見つからない、綴りが違う（Public domain など）、といった場合はすべて失敗になり、曲は取り込まれません。

文法: Python の基本（import・def・型注釈・字下げ）

Python のファイルを読むのに最低限要る 4 つです。このキットの Python のファイル（tools/*.py）はすべてこれを前提にしています。

import — ほかのファイルや標準の部品集（モジュール）を取り込みます。

  • import json は「json というモジュールを取り込み、json.loads(...) のように json.名前 で中身を使えるようにする」。
  • from pathlib import Path は「pathlib の中から Path だけを取り出し、Path と直接書けるようにする」。
  • import urllib.request のように . でつないだ名前は、urllib の中の request という下位のモジュールです。使うときも urllib.request.urlopen(...) と全部書きます。

def — 関数を作ります。

python def header_field(ly_text: str, name: str) -> str | None: match = ... return ...

def 名前(引数, …): の行で始まり、return 値 で呼び出し元に値を返します。return に来ずに最後まで進むと None（値が無いことを表す特別な値）を返します。

型注釈 — ly_text: str の : str は「この引数には文字列が来る」、-> str | None は「戻り値は文字列か None」という注記です。Python は実行時にこれを確かめません（違う型を渡しても動いてしまう）。読む人と、型を検査する道具のための目印です。よく出る型の名前:

書き方 意味
int / float 整数 / 小数
str / bytes 文字列 / バイト列（ファイルの生の中身）
bool True か False
list[dict] 辞書（後述）を並べたリスト
A \| B A か B のどちらか

字下げ — Python は { } を使わず、行頭の空白の深さで「どこからどこまでが関数や if の中身か」を決めます。: で終わる行（def …:、if …:、for …:）の次の行から、1 段深く下げた行が続く間がその中身です。深さを戻した行で中身が終わります。空白の数を間違えると、意味が変わるかエラーになります。

文法: from __future__ import annotations

型注釈（-> str | None など）を、関数を定義した時点では評価せず、文字列のまま持っておくよう指示する 1 行です。これがあると、古い版の Python が知らない str | None のような新しい書き方を注釈に書いてもエラーになりません。ファイルの先頭（docstring の直後）にしか置けません。

文法: パスの組み立て（Path と /）

Path はファイルやフォルダの場所を表す物（オブジェクト）です。

  • __file__ は Python が用意する変数で、いま実行しているファイル自身の場所（ここでは tools/fetch_sources.py）。
  • .resolve() はそれを絶対パスに直し、.parent は 1 つ上のフォルダ。.parent.parent で 2 つ上です。このように . で処理をつないでいく書き方を「メソッドの連鎖」と呼び、左から順に評価されます。
  • Path どうし、または Path と文字列を / でつなぐと、フォルダの区切りを足した新しい Path になります（割り算ではありません）。OS が Windows でも同じ書き方で済みます。

文法: 正規表現と生文字列 r"…"

re.compile(パターン) は、文字列の「形」を表す正規表現を、何度も使える検査器にしておく関数です。.match(文字列) は先頭から形に合うかを、.search(文字列) はどこかに合う部分があるかを調べ、合えば一致の情報（Match）、合わなければ None を返します。

文字列の前の r は「生文字列」の印で、\ を特別扱いしません。正規表現では \s（空白）や \-（ハイフンそのもの）のように \ を多用するので、ふつうの文字列だと \\s と二重に書く必要があり、それを避けるためです。

4 つのパターンを分解します。

SAFE_PATH（L26） — Mutopia 上のフォルダのパス用。

  1. ^ 先頭から
  2. [A-Za-z0-9_\-]+ 英数字・_・- が 1 文字以上（+ は「1 回以上」）
  3. (/[A-Za-z0-9_\-]+)* 「/ と同じ文字の並び」の組が 0 回以上（* は「0 回以上」）
  4. $ 末尾まで

. が使えないので ..（上のフォルダへ戻る）は書けず、/ で始めることも終えることもできません。例 BeethovenLv/WoO59/fur_Elise_WoO59 は通ります。

SAFE_ID（L27） — 曲 ID 用。英小文字・数字・- だけ。曲 ID は保存先のフォルダ名（L57）と、ブラウザが読む public/songs/<id>.json の名前になります。ブラウザ側の src/song/validate.ts も同じ形（docs/design.md の 3 節では ^[a-z0-9-]{1,64}$）を確かめます。

PD_HEADER（L28） — Public Domain の宣言。

  1. ^\s* 行頭と、0 個以上の空白（字下げ）
  2. (license|copyright) license か copyright（| は「または」）
  3. \s*=\s* 空白をはさんだ =
  4. "Public Domain" この綴りそのもの（大文字小文字も区別）

re.MULTILINE を付けると、^ が「文字列全体の先頭」ではなく「各行の先頭」を意味するようになります。.ly のヘッダは \header { … } の中に 1 行ずつ title = "…" の形で並ぶので、行ごとに見る必要があります。

copyright も受け付けるのは、Mutopia の古い版の楽譜が copyright = "Public Domain" と書くためです（docs/research/04-assets-and-licenses.md の 2 節）。収録 12 曲のうち、たとえば arabesque-1 や clair-de-lune は copyright、fur-elise や gymnopedie-1 は license の形です。fur-elise には copyright = \markup { … } という行もありますが、= の後が "Public Domain" ではないのでこちらは一致せず、license の行で通ります。

HEADER_FIELD（L29） — re.compile していない、ただの文字列です。{name} の所に後で項目名を入れて（L51）使います。"([^"]*)" の ( ) は「この部分を取り出す」印（グループ）で、[^"]* は「" 以外の文字が 0 個以上」。つまり引用符の中身を取り出します。

27SAFE_ID = re.compile(r"^[a-z0-9\-]+$")
28PD_HEADER = re.compile(r'^\s*(license|copyright)\s*=\s*"Public Domain"', re.MULTILINE)

文法: リストと辞書

  • リスト [a, b, c] は順番付きの並び。songs[0] で先頭、for song in songs: で 1 つずつ取り出せます。
  • 辞書（dict） {"id": "fur-elise", "path": "…"} は「キー → 値」の対応表。song["id"] でキー "id" の値を取ります。無いキーを [ ] で取ると例外（KeyError）になります。

json.loads(文字列) は JSON の文字列を、Python のリストと辞書の組み合わせに変換します。songs.json は [ {…}, {…} ] の形なので、songs は「辞書のリスト」になります。型注釈 list[dict] はこのことを表しています。

文法: raise による例外

raise ValueError("…") は、処理をその場で打ち切り、エラー（例外）を呼び出し元へ投げます。受け止める処理（try / except）がどこにも無ければ、プログラムはエラーの説明を表示して止まります。ValueError は「値が不正」、L68 の RuntimeError は「実行中の一般的な異常」を表す、標準の例外の種類です。

文法: f 文字列

文字列の前に f を付けると、{ } の中に書いた式の値が埋め込まれます。f"invalid song id: {song['id']!r}" は、song['id'] の値をその場で文字列にして差し込みます。!r は「repr で表示する」指定で、文字列なら 'fur elise' のように引用符付きになります。空白や見えにくい文字が混ざっていても、どこからどこまでが値か分かるようにするためです。

f 文字列の外側を " で囲んでいるので、内側のキーは 'id' と別の引用符で書いています。

load_catalog は目録を読み、全曲の ID とパスを L26-27 の形で確かめてから返します。

  • CATALOG.read_text(encoding="utf-8") で songs.json を文字列として読み、json.loads でリストにする。

文法: not

not x は真偽を反転します。Python では None・0・空の文字列・空のリストは「偽」として扱われるので、not SAFE_ID.match(...) は「一致しなかったら」と読めます。

文法: None と条件式 A if 条件 else B

None は「値が無い」を表す特別な値で、型注釈 str | None は「文字列か、値が無いか」です。

match.group(1) if match else None は、match が真（一致があった）なら match.group(1)、偽（None）なら None、という 1 行の if です。評価の順は 条件 → 選ばれた側で、選ばれなかった側は計算されません。match が None のときに match.group(1) を呼ぶとエラーになるので、この順序が大事です。

header_field は .ly のヘッダから、指定した項目の値を取り出します。

  1. HEADER_FIELD.format(name=name) で、L29 の {name} を項目名に置き換える。name="maintainer" なら ^\s*maintainer\s*=\s*"([^"]*)" になる。
  2. re.search(…, ly_text, re.MULTILINE) で、行頭からその形の行を探す。
  3. 見つかれば group(1)（L29 の ( ) で囲んだ部分＝引用符の中身）を返す。

L75-76 で浄書者（maintainer）と底本（source）を取るのに使います。fur-elise ならそれぞれ Stelios Samelis と Breitkopf & Härtel, 1888 です。項目が無い楽譜では None が返り、meta.json には null と書かれます。

文法: 辞書内包表記

{キー: 値 for 変数 in 並び} は、並びを 1 つずつ取り出して、その都度「キー: 値」を作り、まとめて新しい辞書にする書き方です。

python {ext: {...} for ext, path in files.items()}

files.items() は辞書の「キーと値の組」を順に出します。for ext, path in … はその組を ext と path に分けて受け取ります（2 つの変数で同時に受け取る書き方）。files は {"ly": …, "mid": …} なので、出来上がるのは {"ly": {...}, "mid": {...}} です。

meta は、この曲をどこから、いつ、どの中身で取ったかの記録です。

キー 値 使われる所
id・mutopiaId 目録の値 build_songs.py の L53（クレジット）
pieceUrl Mutopia の曲のページ プレイ前の画面のリンク（src/ui/Play.tsx の L235）

verifiedOn 実行した日（2026-10-08 の形） 記録用

hashlib.sha256(バイト列).hexdigest() は、ファイルの中身から 64 桁の 16 進数の「指紋」を計算します。中身が 1 バイトでも変われば値が変わるので、後で同じファイルかどうかを確かめられます。

L87 は 1 行に処理が詰まっているので、内側から順に:

  2. + "\n" — 末尾に改行を足す。
  3. (song_dir / "meta.json").write_text(…, encoding="utf-8") — UTF-8 で保存する。

最後に meta を返し、main が 1 行の報告に使います。
