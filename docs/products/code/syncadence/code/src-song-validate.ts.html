src/song/validate.ts

takumayellow/syncadence-v2 の main（eb9c698）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

ネット越しに受け取った曲一覧・曲データの JSON が、src/song/types.ts で決めた形に本当になっているかを 1 欄ずつ確かめる、検問のファイルです。

このファイルが担うもの

  • 曲一覧（index.json）を検査して SongSummary の配列として返す parseIndex（L39-52）。
  • 曲データ（<id>.json）を検査して Song として返す parseSong（L54-86）。特に、譜面のノーツが指すレーンと音の添字が範囲内かを確かめます（L72-83）。
  • 曲 ID の形（英小文字・数字・- の 1〜64 文字）を表す正規表現 SONG_ID（L3）。
  • その下ごしらえの小さな関数: オブジェクトか（L7）、数の配列か（L11）、欄が文字列か（L15）・数か（L19）、クレジット（L26）と曲の基本情報（L33）の検査。

TypeScript の型は実行時には消えるので、外から来た JSON の形はこうして実際に調べるしかありません。問題が見つかったら、どこがおかしいかを書いたエラーを投げ、ゲームを始める前に止めます。

  • 調べていない欄もあります。 例えばノーツの時刻が 0 以上か、時刻順に並んでいるか、ロングノーツの長さが 0 以上か、events の音高やベロシティが整数かは調べません。lanes が整数かどうかも調べていません。これらは tools/build_songs.py が正しく作る前提です。

L1–L3

L1 は types.ts から値の DIFFICULTIES と、型の Song・SongSummary を取り込みます。名前の前の type は「これは型だけ」という印です（src/song/load.ts の L1 と同じ）。

文法: 正規表現

/ と / で囲んだものは正規表現という、文字列の形を表すパターンです。SONG_ID の中身を左から読みます。

部分 意味
^ 文字列の先頭
[a-z0-9-] 英小文字・数字・- のどれか 1 文字
{1,64} 直前のものが 1 回以上 64 回以下続く
$ 文字列の末尾

合わせて「先頭から末尾まで全部が英小文字・数字・- で、長さが 1〜64 文字」となります。SONG_ID.test("fur-elise") は真、SONG_ID.test("../x") は偽を返します。^ と $ が無いと、途中に合う部分があるだけで真になってしまうので、両端をしばるのが大事です。

SONG_ID は export されていて、src/song/load.ts の L17 がファイル名を組み立てる前の確認に使います。曲 ID はファイル名 songs/<id>.json になるので、/ や . を含められないこの形に絞っておくと、songs/ の外を指されることがありません。

L4–L9

L5 の type Json = Record<string, unknown>; は、「文字列の欄名を持ち、欄の中身はまだ分からないオブジェクト」に Json という短い名前を付けています（type は文法の索引の『型の別名 type と合併型 |』、Record は『Record 型』、unknown は src/song/load.ts の L6 で説明）。

文法: 型ガード x is T

isObject の戻り値の型 value is Json は、「この関数が true を返したら、引数 value は Json 型だと思ってよい」と TypeScript に教える書き方です。実際に返すのはただの真偽値（true / false）です。

こう書いた関数を if の条件に使うと、TypeScript はその if の内側（true だった側）で value を Json として扱います。unknown のままでは data.version と書けませんが、isObject(data) を確かめた後なら書けるようになります。この「確かめた後で型を狭める」働きを型の絞り込みと呼びます。

L40 の !isObject(data) || … のように「false なら投げる」と書いた場合は、その行より後ろ全体で data が Json 扱いになります。

文法: 実行時の型の確認 typeof と === / !==

式の中に置いた typeof 値 は、その値の種類を "number"・"string"・"object" などの文字列で返します（L2 の型の位置の typeof とは別物で、こちらは実行時に動きます）。

=== は「型まで含めて等しい」、!== は「等しくない」です。JavaScript には == もありますが、1 == "1" が真になるような変換が入るので、このコードでは === を使っています（例外は src/game/session.ts の != null）。

isObject は、{ … } の形のオブジェクトなら真を返します。3 つの条件を &&（かつ）でつないでいます。

  1. typeof value === "object" — オブジェクトの仲間か。ただし JavaScript では、値が無いことを表す null と配列も "object" になります。
  2. value !== null — null を除く。
  3. !Array.isArray(value) — Array.isArray は配列なら真を返すので、!（否定）で配列を除く。
4 
5type Json = Record<string, unknown>;
6 
7function isObject(value: unknown): value is Json {
8 return typeof value === "object" && value !== null && !Array.isArray(value);
9}

文法: every

配列.every(関数) は、配列の全要素について関数を呼び、全部が真を返したときだけ真を返します。1 つでも偽があれば、そこで止めて偽を返します。空の配列には真を返します。

渡している (v) => … はアロー関数（文法の索引の『アロー関数』）で、「要素 v を受け取って、条件の真偽を返す」関数です。

isNumberArray は、「配列で、しかも要素が全部ふつうの数」なら真を返す型ガードです。

Number.isFinite(v) は、v が無限大や NaN（数でない数）ではない、有限の数なら真を返します。JSON には Infinity と書く方法はありませんが、1e999 のように大きすぎる数を書くと、読み込んだときに無限大になります。時刻や音高が無限大だと計算が壊れるので、ここで弾きます。

10 
11function isNumberArray(value: unknown): value is number[] {
12 return Array.isArray(value) && value.every((v) => typeof v === "number" && Number.isFinite(v));
13}

L14–L22

文法: 何も返さない関数 : void

function requireString(…): void の : void は、「この関数は値を返さない」という戻り値の型です。この 2 つの関数は、問題が無ければ黙って終わり、問題があればエラーを投げる、という使い方をします。

文法: 角括弧で欄を読む obj[key]

obj.title は欄の名前をコードに直接書く読み方です。obj[key] は、変数 key に入っている文字列を欄の名前として読みます。key が "title" なら obj.title と同じです。欄の名前を後から決めたいときに使います。

requireString(obj, "title") は「obj の title 欄が文字列でなければ、欄の名前入りのエラーを投げる」関数です。requireNumber は同じことを数について行い、L13 と同じく有限の数であることまで確かめます。

L20 で obj[key] を一度 value に入れているのは、typeof value と Number.isFinite(value) の 2 か所で同じ値を使うためです。

14 
15function requireString(obj: Json, key: string): void {
16 if (typeof obj[key] !== "string") throw new Error(`曲データの ${key} が文字列ではありません`);
17}
18 
19function requireNumber(obj: Json, key: string): void {
20 const value = obj[key];
21 if (typeof value !== "number" || !Number.isFinite(value)) throw new Error(`曲データの ${key} が数値ではありません`);
22}

for (const key of [...]) は、配列の要素を先頭から 1 つずつ key に入れて、後ろの文を繰り返します。番号（0, 1, 2 …）ではなく要素そのものを取り出す繰り返しです。

文法: 型アサーション as

credit.pieceUrl as string は、「credit.pieceUrl の型を string だと思って扱え」と TypeScript に言い切る書き方です。値そのものは何も変わらず、実行時には何の確認もしません。確かめたのは人間の側だ、という宣言です。
