src/audio/regions.ts

takumayellow/syncadence-v2 の main（404da56）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

ピアノの音源の目録を確かめ、「この高さ・この強さの音には、どの録音を使うか」「どのくらいの音量で鳴らすか」を決める、計算だけのファイルです。

このファイルが担うもの

  • 目録 manifest.json の形（SampleManifest・SampleRegion）と、その検査（parseManifest、L21-34）。
  • 強さから、弱い音用と強い音用のどちらの録音を使うかを決める（layerFor、L36-38）。
  • 音の高さから、それを受け持つ録音を探す（findRegion、L41-50）。
  • 録音の先頭の無音の長さを求める（detectAttack、L53-61）。
  • 強さから音量を決める（velocityGain、L64-67）。

音を鳴らしたりファイルを取ってきたりはせず、受け取った値から答えを返すだけです。そのため、試験（src/audio/audio.test.ts）でブラウザ無しに確かめられます。実際に使うのは src/audio/sampler.ts です。

目録の中身。 音源には 66 個の録音があり、目録はそれぞれについて「ファイル名・録音した高さ・受け持つ高さの範囲・弱い音用か強い音用か」を持っています。例えば最初の項目は

{ "file": "A0vH.mp3", "key": 21, "lo": 21, "hi": 22, "layer": "H" }

で、「一番低いラ（高さ 21）を強く弾いた録音で、高さ 21〜22 の強い音に使う」という意味です。強い音用 36 個、弱い音用 30 個で、どちらもピアノの全音域 21〜108 をすき間なく受け持っています。この目録は tools/build_samples.py が、音源に付いてくる SFZ という形式の定義ファイルから作ります。

読みどころ

  • findRegion（L41-50）。受け持ちの範囲に入る録音をまず探し、無ければ録音した高さが一番近いものを使います。
  • velocityGain（L64-67）。強さ 1〜127 を、0.18〜1 の音量に曲線で直します。弱い音でも聞こえるように、下を持ち上げています。

落とし穴

  • parseManifest が確かめるのは一部の欄だけです。 name・license・source の 3 つは調べていません。また regions の中に null のような項目が混ざっていると、L27 で欄を読もうとした所でエラー（TypeError）になります。どちらも、目録はこのプロジェクト自身が作って置くファイルで、外から来る信用できないデータではないので、大きな問題にはなりません。
  • 強さ 81 以上が強い音用です（L37 と目録の velocitySplit: 81）。曲の音の約 83% が強さ 81 以上で、強い音用の録音を使います。
  • findRegion の「一番近い高さで代用する」処理（L45-49）は、今の目録と曲のデータでは使われません。目録が全音域を受け持っており、曲の音の高さは 23〜100 に収まっているからです。

FILE は、ファイル名として受け付ける形を表す正規表現です（src/song/validate.ts の L1-3 の解説）。

  • ^ と $ は、文字列の先頭と末尾です。全体がこの形でなければ合いません。
  • [A-Za-z0-9]+ は、英字か数字が 1 文字以上続くことです。
  • \.mp3 は、文字どおり .mp3 です。. は正規表現では「どんな 1 文字でも」の意味になるので、\ を付けて「点そのもの」にしています。

sampler.ts はこのファイル名を URL の後ろにつないで取ってくる（L34）ので、/ や .. を含む名前を受け付けると、決めた置き場所の外を指してしまいます。英字と数字だけに絞れば、必ず samples/kw/ の中の mp3 を指します（曲 ID を絞る src/song/load.ts の L17 と同じ考え方です）。

parseManifest(data) は、取ってきた目録が正しい形かを確かめ、正しければ SampleManifest として返します。おかしければエラーを投げます。受け取る data の型 unknown は「中身の分からない値」です（src/song/load.ts の L5-10 の解説）。

  1. L22 オブジェクトでなければエラー。typeof null も "object" になるので、null は別に調べます（typeof は src/song/validate.ts の L4-9 の解説）。
  2. L23 欄を読めるように、Record<string, unknown>（「どんな名前の欄でもあってよく、中身は分からない」）とみなす。
  3. L24 velocitySplit が数で、regions が配列でなければエラー。Array.isArray(x) は x が配列なら真を返します。
  4. L25-32 録音の項目を 1 つずつ（for … of。src/song/validate.ts の L23-31 の解説）確かめる。 - ファイル名が文字列で、L19 の形に合う。 - key・lo・hi の 3 つが全部整数。[r.key, r.lo, r.hi] で 3 つを並べた配列をその場で作り、every（src/song/validate.ts の L10-13 の解説）で全部を調べています。Number.isInteger(v) は v が整数なら真です。 - layer が "L" か "H"。
  5. L33 全部通れば、data を SampleManifest とみなして返す。
21export function parseManifest(data: unknown): SampleManifest {
22 if (typeof data !== "object" || data === null) throw new Error("音源の目録が不正です");
23 const m = data as Record<string, unknown>;
24 if (typeof m.velocitySplit !== "number" || !Array.isArray(m.regions)) throw new Error("音源の目録が不正です");
25 for (const r of m.regions as Record<string, unknown>[]) {
26 const ok =
27 typeof r.file === "string" &&
28 FILE.test(r.file) &&
29 [r.key, r.lo, r.hi].every((v) => Number.isInteger(v)) &&
30 (r.layer === "L" || r.layer === "H");
31 if (!ok) throw new Error("音源の目録の項目が不正です");
32 }
33 return data as SampleManifest;
34}

L40–L51

文法: find と findIndex

配列.find(条件の関数) は、条件の関数が真を返す最初の要素を返します。1 つも無ければ undefined です。

配列.findIndex(条件の関数) は、同じく最初に条件に合う要素の番号を返します。1 つも無ければ -1 です。

どちらも、見つかった時点で探すのをやめます。

findRegion(regions, pitch, layer) は、高さ pitch の音に使う録音を返します。

  1. L42 種類が layer の録音だけを filter（文法の索引の『map・filter・reduce』）で取り出して pool にする。
  2. L43-44 その中から、受け持ちの範囲 lo〜hi に pitch が入る最初の録音を find で探し、あれば返す。
  3. L45-49 無ければ、録音した高さ key が pitch に一番近い録音を探して返す。

3 は、全部の録音を順に見て、「まだ候補が無い」か「今の候補より近い」なら候補を入れ替えるやり方です。Math.abs(r.key − pitch) が高さの差の大きさです。比べ方が <（より小さい）なので、差が同じ録音が 2 つあれば先に見たほうが残ります。

L45 の let best: SampleRegion | undefined; は、値を入れずに変数だけを作る書き方です。そうすると最初の値は undefined になります。pool が空なら一度も入れ替わらず、undefined を返します。

例えば弱い音用で高さ 67（ソ）を探すと、Fs4vL.mp3（録音の高さ 66、受け持ち 65〜67）が見つかり、sampler.ts はそれを 1 半音分速く（約 1.0595 倍で）再生します。

40/** 音高を受け持つ区間を探す。見つからなければ、最も近い基準音の区間で代用する。 */
41export function findRegion(regions: readonly SampleRegion[], pitch: number, layer: Layer): SampleRegion | undefined {
42 const pool = regions.filter((r) => r.layer === layer);
43 const exact = pool.find((r) => r.lo <= pitch && pitch <= r.hi);
44 if (exact) return exact;
45 let best: SampleRegion | undefined;
46 for (const r of pool) {
47 if (!best || Math.abs(r.key - pitch) < Math.abs(best.key - pitch)) best = r;
48 }
49 return best;
50}

L52–L62

文法: Float32Array

Float32Array は、小数（32 ビットの浮動小数点数）だけをすき間なく詰めた配列です。ふつうの配列と同じく [番号] で読め、for … of や findIndex も使えますが、数以外は入らず、長さも変えられません。そのぶん大量の数を少ないメモリで速く扱えるので、音の波のデータに使われます。

detectAttack(samples, sampleRate, threshold) は、録音の中で音が立ち上がる位置を秒で返します。

samples は音の波を細かく区切って測った値の列で、1 秒あたり sampleRate 個（例えば 48,000 個）あります。それぞれ −1〜1 の数で、無音なら 0 に近くなります。

  1. L54-55 全部の値の大きさ（絶対値）の最大 peak を求める。
  2. L56 全部 0（完全な無音）なら 0 を返す。
  3. L57 peak の 5%（threshold の既定値 0.05）を境 limit にする。
  4. L58 大きさが初めて limit 以上になる位置を findIndex で探す。ここが「音が立ち上がった所」です。
  5. L59-60 その位置から 2 ms 分（48,000 個毎秒なら 96 個）手前に戻し、秒に直して返す。0 より前にはしません。

2 ms 戻すのは、立ち上がりの直前のごく小さな音まで削ると、打鍵の頭が欠けて硬い音に聞こえるからと読めます（※ 推測: 理由はコードに書かれていません）。

sampler.ts の L37 は、decodeAudioData で直した音のデータの 1 つ目のチャンネル（getChannelData(0)）を渡しています。直した後のデータは AudioContext の 1 秒あたりの個数にそろえられるので、buffer.sampleRate もそれに合わせて渡します。

52/** 立ち上がり（ピーク比 threshold を初めて超える位置）を秒で返す。mp3 の先頭の無音を飛ばすのに使う。 */
53export function detectAttack(samples: Float32Array, sampleRate: number, threshold = 0.05): number {
54 let peak = 0;
55 for (const s of samples) peak = Math.max(peak, Math.abs(s));
56 if (peak === 0) return 0;
57 const limit = peak * threshold;
58 const index = samples.findIndex((s) => Math.abs(s) >= limit);
59 const preRoll = Math.round(sampleRate * 0.002);
60 return Math.max(0, index - preRoll) / sampleRate;
61}

L63–L67

velocityGain(velocity) は、MIDI の強さ（1〜127）から音量（0.18〜1）を決めます。

  1. L65 強さを 1〜127 の範囲に収め（Math.max で 1 未満を 1 に、Math.min で 127 超を 127 にする）、127 で割って 0〜1 の数 v にする。
  2. L66 0.18 + 0.82 × v の 1.6 乗 を返す。
強さ 音量
1 0.1804
40 0.3091
62 0.4403
80 0.5714
81 0.5793
100 0.7394
127 1.0

0.18 を足しているので、どんなに弱い音でも音量は 0.18 より下がりません。L63 のコメントのとおり、弱い音が聞こえなくなるのを防ぐためです。1.6 乗は、強さの差を音量の差として少し強調する曲線です。強さが半分の 63.5 のとき、音量は 0.18 + 0.82 × 0.5 の 1.6 乗 ≒ 0.45 で、最大の半分よりやや下になります。

強い音用と弱い音用で録音そのものの大きさも違うので、実際に聞こえる大きさは、この音量と選んだ録音の両方で決まります。

63/** MIDI ベロシティから音量。強弱の差は残しつつ、弱音でも聞こえるようにする。 */
64export function velocityGain(velocity: number): number {
65 const v = Math.min(Math.max(velocity, 1), 127) / 127;
66 return 0.18 + 0.82 * v ** 1.6;
67}
