tools/build_samples.py

takumayellow/syncadence-v2 の main（eb9c698）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

ゲームの音として鳴らすピアノの録音（FreePats の Upright Piano KW）を取ってきて、ブラウザで読み込みやすい小さな mp3 と、その目録（manifest.json）に作り直すファイルです。

このファイルが担うもの

このゲームは、楽譜の音を 1 つずつピアノの録音で鳴らします（docs/design.md の 1 節）。そのための音源を用意するのがこのファイルです。

  1. 音源の配布元（GitHub の freepats/upright-piano-KW）から、SFZ という音源の設計図と、66 個の FLAC（録音）を取ってくる（fetch）。
  2. SFZ を読み、「どの録音が、どの鍵盤の範囲を、どの強さで受け持つか」を取り出す（parse_sfz）。
  3. 外のプログラム ffmpeg で、各 FLAC をモノラル・最大 7 秒・末尾 1 秒フェードアウトの mp3 にする（transcode）。
  4. 目録 public/samples/kw/manifest.json と、音源の LICENSE・README.md を書き出す（main）。

元の FLAC は合わせて約 33 MB ありますが、作った mp3 は 66 個で 2,761,770 バイト（約 2.8 MB）です。ブラウザは曲に要る分だけを読み込みます（src/audio/sampler.ts の L20-27）。

読みどころ

  • parse_sfz（L43-69）。SFZ という文字の設計図を、1 行ずつ「状態」を持ちながら読む、小さな読み取り器です。
  • SAFE_SAMPLE（L26）と L93-95。ネットから取ってきた設計図に書かれたファイル名を、そのまま信用しないための検査です。
  • transcode（L72-82）。音を 7 秒で切ってフェードアウトする ffmpeg の指定です。
  • docstring の L7。mp3 の先頭の無音をここでは削らず、ブラウザ側で打ち消す、という役割の分け方です。

落とし穴

  • 7 秒より長い音は、6 秒からフェードアウトして 7 秒で消える。 元の FLAC 66 個のうち 21 個が 7 秒より長く、一番長いものは約 13.3 秒です。SFZ には低音の録音を延々と伸ばすためのループの位置（loop_start・loop_end）が書いてありますが、parse_sfz はそれを読まないので、ブラウザでは長く伸ばした低音も 7 秒で消えます。
  • 作り済みの mp3 は作り直さない。 L98 で、同じ名前の mp3 があれば変換を飛ばします。MAX_SECONDS や BITRATE を変えたときは、古い mp3 を消してから動かす必要があります。
  • この SFZ の書き方に合わせた読み取り器。 <region> が 1 行に単独で書かれていること、層を hivel=80 と lovel=81 で分けていることを前提にしています。別の音源の SFZ では、L94-95 の検査で止まるか、正しく読めません。
  • ffmpeg が要る。 見つからなければ、L86-88 で何もせずに終了コード 1 で終わります。

7 秒・80 kbps の mp3 は、7 × 80,000 ÷ 8 = 70,000 バイトです。実際の一番大きい mp3 は 70,576 バイトで、ファイルの見出しなどの分だけ少し多くなっています。一番小さいのは、元の録音が短い高音の C8vL.mp3 で 4,747 バイトです。

文法: 文字列の分割と空白の除去

  • text.splitlines() は、文字列を改行で区切った、行のリストを返します。
  • raw.split("//", 1) は、// で区切ったリストを返します。2 つ目の引数の 1 は「区切るのは最初の 1 か所だけ」で、結果は [前, 後ろ] の 2 つ以下になります。[0] で前だけを取ります。
  • .strip() は、前後の空白と改行を取り除いた文字列を返します。

どれも元の文字列は変えず、新しい文字列やリストを返します。

文法: 正規表現で全部探す findall

OPCODE.findall(line) は、line の中で形に合う所をすべて探し、リストにして返します（.match が先頭の 1 か所だけを見るのと違います。文法の索引の『正規表現と生文字列 r"…"』）。形に ( ) が 2 つあるので、1 つの要素は (名前, 値) の組になります。" lokey=21 hikey=22" なら [("lokey", "21"), ("hikey", "22")] です。

文法: 辞書の書き換え .update

current.update(lokey=21, hikey=21, pitch_keycenter=21) は、辞書 current に、キーワード引数の名前をキーとして、まとめて値を入れます（あれば上書き）。L64 の current[key] = … を 3 回書くのと同じです。

parse_sfz は、SFZ の文字を読んで、region（区域）ごとの辞書のリストを返します。

SFZ の書き方。 使う音源の設計図は、次のような形をしています（一部）。

<group>
 hivel=80
 loop_mode=loop_continuous
<region>
 lokey=21 hikey=22
 pitch_keycenter=21
 sample=samples/A0vL.flac
<region>
 key=23
 sample=samples/B0vH.flac

<group> から次の <group> までが 1 つのまとまりで、その頭に、まとまり全体の決まり（hivel=80 は「強さ 80 以下で鳴らす」）を書きます。<region> の後に、その録音が受け持つ鍵盤の範囲（lokey〜hikey）、録音した鍵盤（pitch_keycenter）、録音のファイル（sample）を書きます。key=23 は「23 の鍵盤 1 つだけで、録音した鍵盤も 23」の省略形です。鍵盤の番号は MIDI の番号で、21 がピアノの一番低い A0、108 が一番高い C8 です。

読み方。 2 つの「今の状態」を持ちながら、1 行ずつ読みます。

変数 意味
layer 今のまとまりの層（"L" か "H"）。最初は None
current 今書き込んでいる region の辞書。まとまりの頭では None
  1. L48: // から後ろ（コメント）を捨て、前後の空白を取る。
  2. L49-50: 空の行は飛ばす（文法の索引の『continue』）。
  3. L51-53: <group> なら、今の region を終わりにする。この後に書かれた hivel などを、前の region に書き込まないためです。
  4. L54-57: <region> なら、今の層を入れた新しい辞書を作り、リストに足し、それを今の region にする。辞書はリストに入れた後も同じ 1 個の物なので、この後 current に書き込むと、リストの中の辞書にも反映されます（文法の索引の『is』）。
  5. L58-68: それ以外の行は、「名前=値」をすべて探し、名前で場合分けする（文法の索引の『elif』）。 - hivel=80 なら、層を "L"（弱）にする。 - lovel=81 なら、層を "H"（強）にする。 - region の中で lokey・hikey・pitch_keycenter なら、整数にして入れる。 - region の中で key なら、3 つすべてに同じ値を入れる。 - region の中で sample なら、ファイル名を入れる。 - それ以外（loop_mode・loop_start など）は読まずに捨てる。

L63 の key in ("lokey", "hikey", "pitch_keycenter") は、3 つのどれかに当たるかを in で確かめています（文法の索引の『in による所属の判定』）。

この音源の設計図は 360 行で、<group> が 4 つ（弱い層 2 つ・強い層 2 つ）、<region> が 66 個あります。弱い層は 30 個、強い層は 36 個です。弱い層は A0 から C8 まで 3 半音おきに録音していて、間の鍵盤は近くの録音で代用します。

1 つの例。 最初の region は {"layer": "L", "lokey": 21, "hikey": 22, "pitch_keycenter": 21, "sample": "samples/A0vL.flac"} です。21（A0）と 22（A#0）を、A0 の録音で鳴らします。22 を鳴らすときは、ブラウザが再生の速さを 2 の 12 分の 1 乗（約 1.059）倍にして、半音上げます（src/audio/sampler.ts の L53）。

文法: 外のプログラムを動かす subprocess.run

subprocess.run([プログラム名, 引数1, 引数2, …], check=True) は、別のプログラムを動かし、終わるまで待ちます。

  • 引数をリストで渡すと、1 つ 1 つの要素がそのまま 1 つの引数になります。ファイル名に空白や記号が入っていても、命令の区切りと取り違えられません。
  • check=True を付けると、プログラムが失敗（終了コードが 0 以外）したときに例外を出して止まります。付けないと、失敗しても何も言わずに先へ進みます。

transcode は、ffmpeg で FLAC（src）を mp3（dst）に変換します。L73 で、フェードアウトを始める秒（7.0 − 1.0 = 6.0）を計算しておきます。渡す引数を、意味ごとに分けると次のとおりです。

引数 意味

-loglevel error エラーのときだけ表示する
-i 元のファイル 読み込むファイル

書き出し先のファイル

L78 の f 文字列（文法の索引の『f 文字列』）の中で、MAX_SECONDS などの小数は 7.0・6.0・1.0 と書かれます。7 秒より短い録音では、atrim は何も切らず、afade の 6 秒も音の終わりより後なので、何も変わりません（たとえば A4vH.flac は約 2.96 秒）。

モノラルにするのは、ゲームでは左右の広がりよりも、読み込む量を半分にする方が大事だからと考えられます（※ 推測）。元の録音はステレオです（docs/research/04-assets-and-licenses.md の 3 節）。

str(src) は Path を文字列に直しています。subprocess.run の引数のリストには、文字列をそろえて渡します。

文法: エラーの出力先 sys.stderr

print(…, file=sys.stderr) は、ふつうの出力（標準出力）ではなく、エラー用の出力（標準エラー出力）に表示します。画面ではどちらも同じように見えますが、出力をファイルに保存したときも、エラーは画面に残ります。

文法: フォルダの中を探す glob とファイルの大きさ

OUT.glob("*.mp3") は、フォルダ OUT の中で、名前が .mp3 で終わるファイルの Path を順に出します（* は「どんな文字の並びでも」）。p.stat().st_size は、そのファイルの大きさ（バイト数）です。
