src/ui/Play.tsx

takumayellow/syncadence-v2 の main（404da56）の写し。コードは 1 文字も変えていない。右の解説はこのサイトだけのもの。

プレイ画面そのものです。曲と音源を読み込み、毎フレーム「進行を 1 歩進めて絵を描く」ループを回し、キーボードとタッチの入力を進行役（PlayEngine）に渡し、READY・PAUSE などの重ね表示を出し分けます。

このファイルが担うもの

  • 曲の JSON と、その曲に要るピアノの音源を読み込み、読み終えたら PlayEngine（src/game/engine.ts）を 1 つ作る（L45-68）。
  • requestAnimationFrame で画面の書き換えのたびに engine.tick（進行と判定）と engine.frame → drawFrame（描画）を呼ぶ（L71-102）。
  • キーの押し下げ・離し、指やマウスの押し下げ・離しを、レーン番号と押した瞬間の時刻にして engine.press / engine.release に渡す（L105-189）。
  • Esc・タブの切り替え・ウィンドウからフォーカスが外れたとき・スマホを縦に持ち直したときの一時停止と再開（L36-43, L123-134, L162-169）。
  • 画面の上の帯（曲名・難易度・一時停止ボタン）と、読み込み中・エラー・READY・PAUSE の重ね表示（L193-266）。

ゲームの中身（時計・音の予約・判定）はこのファイルにはありません。ここは「React の画面」と「ゲームの進行役」をつなぐ配線役です。

読みどころ

  • 2 つの「状態」。画面の出し分けは React の phase（L30）、ゲームの進み具合は engine.state（src/game/engine.ts の L71）が持ちます。キー入力の判断は engine.state を見て、重ね表示は phase を見ます。
  • 描画ループ loop（L79-99）。1 フレームの中で「進める（tick）→ 終わったら結果へ → 大きさを合わせる → 描く（frame → drawFrame）」の順です。
  • 入力の時刻は e.timeStamp（L137, L142, L154, L160）。ハンドラが動いた時刻ではなく、ブラウザが記録した「押された瞬間」を渡します。
  • useRef で作り直しを避ける（L32-34）。設定やコールバックが変わっても、プレイ中の進行役や描画ループを作り直さないための仕掛けです。

落とし穴

  • キーを押したままウィンドウから外れると、そのレーンが押しっぱなし扱いで残ることがあります。 blur で一時停止する（L177）だけで、押していたレーンを離した扱いにはしません。フォーカスが外れている間に指を離すと、その keyup はこのページに届かず、PlayEngine の pressedLanes が true のまま残ります。戻ってから同じキーを押しても、press は「押しっぱなし」とみなして 1 回目を捨てます（src/game/engine.ts の L146）。※ 推測: フォーカスの外れた間の keyup が届かないのはブラウザの一般的な挙動で、この画面で確かめたわけではありません。
  • 曲の途中で設定を変えても効きません（L32）。settingsRef は最初の値を覚えるだけで、以後は更新しません。プレイ中に設定を変える画面は無いので、いまは問題になりません。

L20–L24

プレイ画面がいまどの段階にいるかを表す型です。L198 からの見た目の出し分けはすべてこの値で決まります（文法の索引の「型の別名 type と合併型 |」）。

文法: kind で見分ける合併型

Phase は 3 種類の形のどれか 1 つです。

  • { kind: "loading"; done: number; total: number } — 読み込み中。音源を何個読み終えたか（done）と全部で何個か（total）を持つ
  • { kind: "ready" | "playing" | "paused" } — 開始待ち・プレイ中・一時停止中。ほかの情報は持たない
  • { kind: "error"; message: string } — 失敗。画面に出す文言を持つ

どの形にも kind という同じ名前の欄があり、そこに入る文字列で形が決まります。if (phase.kind === "loading") と確かめた後なら、TypeScript は「この中では phase.done がある」と分かるので、phase.done と書いても怒りません。逆に、確かめずに phase.message と書くと「message が無い形もある」と止めてくれます。

ready / playing / paused の 3 つは中身が同じなので、1 つの形の中で "ready" | "playing" | "paused" とまとめています。

engine.state（src/game/engine.ts の EngineState）にも ready / playing / paused がありますが、こちらは画面の見た目のための写しです。engine.start() は呼ばれた瞬間に engine.state を playing にしますが、phase が playing になるのは音の準備（ctx.resume()）が済んだ後です（L109）。

文法: useRef

useRef(初めの値) は、React の部品が作り直されても同じ箱を返し続けるフックです。箱の中身は .current で読み書きします。

useState との違いは、中身を書き換えても画面が描き直されないことです。描き直しを起こしたくない値（毎フレーム変わる値、関数、DOM 要素）を持っておくのに使います。

もう 1 つの使い方が L196 の <canvas ref={canvasRef} /> です。JSX で ref={箱} と書くと、React はその要素を画面に置いた後、箱の .current にその要素を入れてくれます。L72 の canvasRef.current で canvas 要素そのものに手が届くのはこのためです。

L26 は props の分割代入です（文法の索引の「分割代入」）。受け取った 1 つのオブジェクトから 6 つの値を取り出して、同じ名前の変数にしています。

L35–L43

一時停止と再開の関数です。ボタン（L199, L254）、Esc（L125-126）、タブの切り替え（L163）、フォーカスの外れ（L177）から呼ばれます。どちらも useCallback で包んであるので、engine が変わらない限り同じ関数のままです（文法の索引の「useCallback」）。同じ関数のままであることが L189 で効きます。

再開 resume（L36-38）

  1. engine が null（まだ読み込み中）なら何もしない
  2. engine.resume() を呼ぶ。これは音の時計（AudioContext）を動かし直すので、終わるまで少し待つ
  3. 終わったら phase を playing にする。PAUSE の重ね表示が消える

void engine.resume().then(…) の void は文法の索引の「void 演算子」、.then は「async / await と Promise」を見てください。「終わるのを待たずにこの関数は抜ける。終わったら .then の中を実行する」という書き方です。

一時停止 pause（L39-43）

engine?.state !== "playing" は、engine が null なら undefined、そうでなければ engine.state になります（文法の索引の「オプショナルチェーン ?. と ??」）。どちらにしても「プレイ中でなければ何もしない」という意味です。READY の画面でウィンドウを切り替えても、一時停止にはなりません。

プレイ中なら engine.pause() で進行を止め、phase を paused にして PAUSE の重ね表示を出します。engine.pause() は待つ必要が無いので、resume と違って .then を使いません。

文法: 作ってすぐ呼ぶ async 関数

(async () => { … })() は、「async のアロー関数を作り、すぐその場で呼ぶ」書き方です。外側の ( … ) で関数をくくり、最後の () で呼んでいます。

文法: && の短絡評価

A && B は、A が偽ならそこで止まって B を評価しません。A が真のときだけ B を実行します。L55 の !cancelled && setPhase(…) は「画面がまだ開いていれば、読み込みの進み具合を表示に反映する」を 1 行で書いたものです。if (!cancelled) setPhase(…) と同じ動きです。

文法: unknown と instanceof

(e: unknown) は「e が何なのか分からない」という型です。JavaScript では throw で何でも投げられるので、受け取る側は中身を確かめてからでないと使えません。

e instanceof Error は「e は Error（またはその仲間）から作られた物か」を調べます。真なら、その後では e.message（エラーの文言）が使えます。

文法: 条件演算子 ? :

条件 ? A : B は、条件が真なら A、偽なら B になる式です。if 文と違って値になるので、代入の右辺や関数の引数の中に書けます。

L62 は「e がエラーならその文言を、そうでなければ『読み込みに失敗しました』を message にする」です。

描画と進行のループです。engine と song がそろい、canvas が画面に置かれた後で動き始めます。

L72-75 は前提の確認です。canvas.getContext("2d") は canvas に絵を描くための道具（2D の描画コンテキスト）を返します。道具を使った描き方は文法の索引の「Canvas 2D」を見てください。

L78 の window.matchMedia?.(TOUCH_QUERY) は、「マウスを重ねる（ホバーする）手段が無く、指のように粗い指し方しかできない端末か」を CSS の条件でたずねます。条件の中身 "(hover: none) and (pointer: coarse)" は src/ui/landscape.ts に 1 つだけ書いてあり、全画面に入るか・横向きの案内を出すかの判定も同じ文字列を使います。?.(…) は「matchMedia という関数があれば呼び、無ければ undefined」の意味で（文法の索引の「オプショナルチェーン ?. と ??」の関数呼び出し版）、最後の ?? false で無いときは false にします。タッチだけの端末ならレーンの下に D・F・J・K のようなキーの名前を出しません（L98）。

文法: requestAnimationFrame

requestAnimationFrame(関数) は、「ブラウザが次に画面を書き換える直前に、この関数を 1 回呼んで」と頼む命令です。呼ばれるのは 1 回だけなので、毎フレーム動かしたいときは、呼ばれた関数の中でもう一度頼みます（L80）。画面が 1 秒に 60 回書き換わる端末なら約 16.7 ms ごと、120 回なら約 8.3 ms ごとに呼ばれます。タブが裏に回ると呼ばれなくなります。

戻り値は頼みごとの番号です。cancelAnimationFrame(番号) で頼みを取り消せます（L84, L101）。

1 フレームの中身（L79-99）

  1. 次のフレームを先に頼む（L80）。途中で何かが失敗しても、ループが止まらないようにするためです。
  2. いまの時刻を取る（L81）。performance.now() はページを開いてからの経過ミリ秒で、小数まで細かく、止まらず、巻き戻りません。このファイルで扱う時刻はすべてこの物差しです。
  3. 進める（L82）。engine.tick(now) が、音の予約・見逃しの判定・オートプレイを 1 歩進め、曲が終わったら true を返します（src/game/engine.ts の L178-192）。
  4. 終わったら結果画面へ（L82-86）。finished で 2 度呼ばないようにし、1 で頼んだ次のフレームを取り消し、onFinish に曲・難易度・成績（engine.stats()）を渡します。App.tsx が結果画面に切り替えると、この画面は閉じられ、L64-67 の後片付けが走ります。
  5. canvas の大きさを合わせる（L88-94）。
  6. 描く（L95-98）。engine.frame(now) が「いま描くべきもの」をまとめ、drawFrame がそれを描きます。

canvas の大きさ（L88-95）

canvas には 2 つの大きさがあります。

  • canvas.clientWidth / clientHeight — 画面に見えている大きさ（CSS のピクセル）
  • canvas.width / height — 絵を描きこむ画素の数

スマートフォンや高解像度の画面では、CSS の 1 ピクセルに実際の画素が 2〜3 個並びます。この比が window.devicePixelRatio（dpr）です。画素の数を CSS の大きさのままにすると絵がぼやけるので、L91-94 で 見えている大きさ × dpr にそろえます（ずれているときだけ。canvas の大きさを変えると中身が消えるため、毎フレームは変えません）。

L95 の g.setTransform(dpr, 0, 0, dpr, 0, 0) は「この後に描く座標を dpr 倍に引き伸ばす」設定です。これで drawFrame は CSS のピクセルのつもりで width × height の中に描けば、実際の画素に合わせて細かく描かれます。毎フレーム設定し直すのは、大きさを変えると設定が初めに戻るからです。

L98 の { ...frame, keyLabels: [] } は、frame の中身を写したうえで keyLabels だけを空にした新しいオブジェクトです（文法の索引の「スプレッド構文 ...」）。frame そのものは書き換えません。

一時停止中もループは回り続けます。 tick は何もせずに false を返し（src/game/engine.ts の L180）、frame は一時停止した瞬間の時刻で絵を作るので（同 L195）、同じ絵を描き続けます。

後片付け（L101） は、画面が閉じられるときにループを止めます。依存の並び [engine, song, difficulty]（L102）は読み込みが終わったときに 1 回変わるだけなので、ループが作り直されるのは実質その 1 回です。

(e: KeyboardEvent) はキーボードのイベントです。使う欄は 3 つです。

L144–L161

指・マウス・ペンで押したときと離したときです。ブラウザはこの 3 つを「ポインター」という 1 つの仕組みで扱います。

文法: Map と Set

new Map<number, number>() は、鍵と値の組をしまう入れ物を作ります。<number, number> は「鍵も値も数」という指定です。

書き方 意味
m.set(鍵, 値) 組を入れる（同じ鍵があれば上書き）
m.get(鍵) 鍵に対応する値。無ければ undefined
m.delete(鍵) 組を取り除く
m.has(鍵) 鍵があるか

Set は値だけをしまう入れ物で、同じ値は 1 つしか入りません。s.add(値) で入れ、s.has(値) で入っているかを調べます（src/game/engine.ts の L60）。

オブジェクト {} でも似たことはできますが、Map は鍵に数をそのまま使え、出し入れが頻繁でも速く、get で無いときは必ず undefined が返る、という点で入れ物専用に向いています。

pointerLanes は「どの指が、どのレーンを押したか」の表です。鍵は e.pointerId（指ごとにブラウザが振る番号）、値はレーン番号です。

押したとき（L146-155）

  1. e.preventDefault() で、ブラウザ本来の動き（長押しのメニューなど）を止める
  2. 開始待ちなら、タップを開始の合図にする（L148-151）。READY の重ね表示は CSS で pointer-events: none（タップを素通しする設定）になっているので、タップは下の canvas に届きます
  3. laneAt(e.offsetX, …) で、canvas の左端からの横位置をレーン番号に直す（L152）。レーンは奥ほど狭い台形なので、判定線のあたりでの幅で割り振ります（src/render/highway.ts の L70-72）
  4. 指とレーンの組を覚え、engine.press を呼ぶ

離したとき（L156-161）

指を離したときは、押したときのレーンを表から引いて離します。指を横に滑らせて別のレーンの上で離しても、押したレーンを離したことになります。表に無い指（canvas の外で押した指など）は無視します。

離す方は canvas ではなく window で受けます（L174-175）。指が canvas の外へ出てから離れても取りこぼさないためです。pointercancel（端末がジェスチャーとして指を横取りしたときなど）も離したのと同じに扱います。

L162–L189

onVisibility（L162-164）は、タブが裏に回ったとき（document.hidden が true）に一時停止します。裏に回ると requestAnimationFrame が止まり、ノーツが流れているのに判定が進まなくなるからです。

onOrientation（L165-169）は、スマホを縦に持ち直したときに一時停止します。縦に持つと「横向きにしてください」の案内（src/ui/RotateHint.tsx）がレーンの上に重なり、叩けないまま曲が進んでしまうからです。L166 の window.matchMedia?.(PORTRAIT_TOUCH_QUERY) は、条件に合っているかをその場で答えるだけでなく、合う・合わないが変わったときに知らせてくれる物（MediaQueryList）を返します。L178 でその change に onOrientation を登録し、知らせが来たら portrait?.matches（いま縦か）を見て、縦になったときだけ止めます。横に戻したときは止めたままにして、PAUSE の重ね表示の「続ける」で自分から再開してもらいます。

文法: イベントリスナーの登録と解除

対象.addEventListener("種類", 関数) は、「この種類の出来事が起きたら、この関数を呼んで」とブラウザに登録する命令です。関数には、出来事の詳しい情報（イベントのオブジェクト）が引数で渡されます。

対象.removeEventListener("種類", 関数) で登録を取り消します。取り消すには登録したときと同じ関数を渡す必要があります。中身が同じでも、別に作った関数では取り消せません。

React の useEffect の中で登録したら、後片付けの関数で必ず取り消します。取り消さないと、画面を閉じた後もリスナーが残り、閉じた画面の進行役にキー入力が届き続けます。
