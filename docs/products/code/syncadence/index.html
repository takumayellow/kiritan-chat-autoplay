Syncadence のコードを読む

ピアノの名曲の楽譜から譜面を作り、ブラウザで叩くリズムゲーム。 楽譜のファイルが譜面になるまでと、画面のノーツを 1 つ叩いて判定が出るまでの 2 本の流れを、 1 行ずつたどって読むための資料。

読んでいるのは takumayellow/syncadence-v2 の main（404da56）時点。コードの写しは 1 文字も変えていない。解説はコードの横に置いてあり、コードそのものには混ぜていない。

コード

1 ファイル 1 ページ。元コードを行番号つきで区切り、区切りごとに解説が付いている。

画面 (src/ui)

  • App.tsx123 行いまどの画面（選曲・プレイ・結果・タイミング調整）を出しているかを 1 つの値で覚え、その値に応じて画面の部品を 1 つだけ選んで描く、ゲーム全体の「司令塔」の部品です。
  • Calibrate.tsx132 行0.6 秒おきに 20 回鳴るクリック音に合わせてキーか画面を叩いてもらい、音が聞こえてから押すまでのずれの中央値を測って「入力の補正」に入れる、タイミング調整の画面の部品です。
  • Play.tsx267 行プレイ画面そのものです。曲と音源を読み込み、毎フレーム「進行を 1 歩進めて絵を描く」ループを回し、キーボードとタッチの入力を進行役（PlayEngine）に渡し、READY・PAUSE などの重ね表示を出し分けます。
  • Result.tsx90 行1 曲を遊び終えた後に、ランク・スコア・判定ごとの回数・最大コンボと、押したタイミングの偏りを出し、偏りが大きければ「入力の補正」の変更を 1 ボタンで提案する結果画面の部品です。
  • RotateHint.tsx11 行スマホを縦に持っている間だけ、ゲームの上に「画面を横向きにしてください」と重ねて出す部品です。出すか隠すかは、この部品ではなく CSS（src/styles/rotate.css、解説キット外）が決めます。
  • SettingsPanel.tsx82 行ノーツの速さ・テンポ・音量・2 つの補正・キー音・オートプレイの 7 つの設定を、スライダーや入力欄やチェックボックスで変えられるようにする設定の部品です。
  • SongSelect.tsx176 行左に曲の一覧、右に選んだ曲の詳細（難易度ごとのレベル・ノーツ数・ランク、自己ベスト、PLAY ボタン）を並べ、矢印キーと Enter でも操作できる選曲画面の部品です。
  • landscape.ts62 行スマホで遊ぶときに、画面をタップしたら全画面に入り、横向きに固定する仕組みと、「指で触る端末か」「それを縦に持っているか」をたずねる CSS の条件を置いたファイルです。
  • select.ts26 行選曲画面（src/ui/SongSelect.tsx）が使う 4 つの小さな計算、つまりジャケットの色と文字、↑↓←→ での移動先を、画面の部品から切り離して置いたファイルです。

進行と判定 (src/game)

  • engine.ts220 行1 プレイ分の進行役 PlayEngine です。曲の 0 秒をいつ鳴らすかを決めて音を予約し、入力の時刻を「そのとき聞こえていた曲の位置」に直して判定に回し、毎フレーム描画に渡す材料をまとめます。
  • judge.ts31 行押した時刻のずれ（ミリ秒）を PERFECT・GREAT・GOOD・MISS のどれかに決める「判定幅」と、判定ごとのスコアの重みを決めておくファイルです。
  • keys.ts22 行どのキーがどのレーンに当たるか、そして曲を始める合図にどのキーを使ってよいかを決める、小さな表と 3 つの関数です。
  • rank.ts14 行スコア（0〜1,000,000）から SSS〜D のランクを決める表と、それを引く関数です。
  • session.ts185 行1 回のプレイの「どのノーツをもう叩いたか」「コンボはいくつか」「スコアはいくつか」を覚えておき、押した・離した・時間が経った、の 3 つの出来事から判定を出すファイルです。
  • stats.ts39 行押したタイミングのずれを数でまとめる関数です。結果画面の「早め・遅め」の表示と、タイミングを測る画面の「入力の補正」の値は、ここで計算します。

音と時計 (src/audio)

  • clock.ts68 行「いまスピーカーから聞こえているのは曲の何秒目か」を、ブラウザの 2 つの時計の対応から求めるファイルです。
  • context.ts17 行ブラウザで音を鳴らすための土台 AudioContext と、ピアノの音源 Sampler を、アプリ全体で 1 組だけ作って使い回すためのファイルです。
  • regions.ts67 行ピアノの音源の目録を確かめ、「この高さ・この強さの音には、どの録音を使うか」「どのくらいの音量で鳴らすか」を決める、計算だけのファイルです。
  • sampler.ts64 行本物のピアノを 1 音ずつ録音した音（サンプル）を読み込んでおき、指定された高さ・強さ・時刻・長さでその音を鳴らす、ゲームの「ピアノ」にあたるファイルです。
  • scheduler.ts35 行曲の伴奏の音を、いまの位置から 0.4 秒先までずつ、AudioContext に「この時刻に鳴らして」と前もって予約していくファイルです。

描画 (src/render)

  • highway.ts422 行プレイ画面の 1 コマ（レーン・拍の線・ノーツ・判定線・光・判定の文字・コンボ・スコア・進み具合）を、canvas に毎フレーム描き直すファイルです。
  • perspective.ts86 行奥から手前へ流れるレーンの「どこに何を描くか」を、画面の大きさと時刻から計算する、絵を 1 枚も描かない計算専用のファイルです。

曲データの読み込み (src/song)

  • load.ts19 行サーバーに置いた曲一覧と曲データの JSON を、ブラウザからネット越しに取ってきて、形を確かめてから渡すファイルです。
  • types.ts55 行曲データ（public/songs/<id>.json）と曲一覧（public/songs/index.json）が、どんな形の値なのかを TypeScript の「型」として書き下したファイルです。
  • validate.ts86 行ネット越しに受け取った曲一覧・曲データの JSON が、src/song/types.ts で決めた形に本当になっているかを 1 欄ずつ確かめる、検問のファイルです。

入口と保存 (src)

  • main.tsx14 行ブラウザがページを開いたときに最初に動き、画面全体を描く部品 App と、縦持ちのときに重ねる案内 RotateHint を、HTML の空の箱 <div id="root"> の中に描き始めるだけの、14 行の入口です
  • storage.ts119 行設定・自己ベスト・最後に選んだ曲と難易度を、ブラウザの中の小さな保存場所（localStorage）に書き込み、次に開いたときに読み戻すファイルです。読み戻した値は型と範囲を 1 つずつ確かめ、壊れていれば既定値に戻しま

譜面を作る (tools・Python)

  • build_samples.py123 行ゲームの音として鳴らすピアノの録音（FreePats の Upright Piano KW）を取ってきて、ブラウザで読み込みやすい小さな mp3 と、その目録（manifest.json）に作り直すファイルです。
  • build_songs.py98 行保存してある楽譜から、ゲームが読み込む曲データ（public/songs/<曲ID>.json）と曲の一覧（public/songs/index.json）を書き出すファイルです。
  • chart.py353 行楽譜データ（tools/score.py の Score）から、EASY・NORMAL・HARD・EXPERT の 4 つの譜面を自動で作るファイルで、このゲームの譜面の形はすべてここで決まります。
  • fetch_sources.py102 行Mutopia Project から曲ごとの楽譜（LilyPond の .ly）と MIDI を取ってきて、楽譜のヘッダに「Public Domain」と書かれていない曲を止める、取り込みの入口のファイルです。
  • score.py230 行MIDI ファイルを読み、「どの音が、何秒に、どちらの手で、拍のどれくらい強い位置で鳴るか」を引ける楽譜データ（Score）に変える、譜面づくりの土台のファイルです。

このサイトの作り

ピアノの名曲を、楽譜から自動で作った譜面で叩くブラウザのリズムゲーム「Syncadence」を、楽譜のファイルが譜面になるまで（Python）と、ノーツ 1 つが流れてきて判定されるまで（TypeScript）の 2 本の筋でたどって読むための資料。本線の 32 ファイルを丸ごと写し、1 行ずつ解説を付けてある。TypeScript・React・Python の書き方を知らなくても読めるよう、出てきた書き方はその場で説明している。

読む対象はコミット 404da56（main）。

サイトを作る

pip install git+https://github.com/takumayellow/code-reading-kit
python -m learnkit check docs/learning
python -m learnkit build docs/learning

docs/learning/site/index.html を開けば読める。site/ は生成物なので追跡しない。

元のコードが進んだら、kit.toml の [source].commit を上げて check を回すと、変わったファイルが落ちる。そのファイルだけ写し直して、解説の行範囲を直す。

スクリーンショットを撮り直す

npm run dev
pip install playwright pillow && python -m playwright install chromium
python docs/learning/tools/shots/take_shots.py http://localhost:5173/

assets/shots/ の 6 枚を上書きする。結果画面は、譜面のノーツを人が叩いたように時刻を揺らして（平均 +18 ms・標準偏差 22 ms）押して撮っている。
